## 第 3 章 处理器微架构设计

本章按"评审可感知度"排序：3.1 顺序双发射（最大差异化）→ 3.2 双发射的第二级：lane B 可访存 →
3.3 多层动态分支预测 → 3.4 load 地址提前（EARLY_LD）→ 3.5 取指时序契约与停顿补偿 →
3.6 多拍除法器与 II=1 乘法器 → 3.7 前递路径与写通路 → 3.8 RV32A 的可配置取舍。
每一节都按同一个叙事模板写：**设计动机 → 判据（写进 RTL 的条件）→ 量化收益 → 代价与验证**，
因为"设计—收益—代价"的闭环才是工程判断力的证据，单报收益反而是选择性呈现。

本章所有周期数都是指 **CoreMark 计时区间内每迭代的 CPU 周期数**（`region` 口径，
来源 `doc/reports/2026-10-16_session_state_p3_5.md`、`..._p3_6_margin_plan.md`），
所有效率值都是 **CoreMark/MHz = 时钟 ÷ 每迭代周期数**（赛题公式
`Score = Iterations/(Total_Time × Frequency)` 化简后的等价形式）。

### 3.1 顺序双发射（2-wide in-order）

**设计动机。** 五级流水（IF/ID/EX/MEM/WB）的单发射版本已经用尽了"取指 1 拍、
前递消 RAW"能拿到的效率（312,428 → 300,392 拍/迭代的两轮修改后收益趋平）。
进一步提升每拍提交指令数有三条路：乱序（对学生设计而言验证成本过高）、
VLIW/超长指令（需要重新设计 ISA，不现实）、**受限顺序双发射**——我们选了第三条：
每拍从取指端取两条相邻指令，交给 lane A / lane B 两个执行槽，**只有在静态可判定的
条件下才允许第二槽发射**。

**配对判据（写进 RTL 的条件）。** 配对判定必须落在"取指数据到达级"而不是 ID 级，
否则取指永远慢一拍、IF/ID 会把第二槽重复消费一次（那正是"必须加取指队列"这个
结论的来源）。把判定提前到到达级后，`fetch_addr` 直接由配对结果组合算出（+4/+8），
两槽天然对齐、不需要指令队列。判据本身是一张保守白名单：

1. **lane A 是合法指令**，且不是多拍单元的所有者（乘除、AMO 禁止配对——它们会让
   lane A 与 lane B 一起冻在 ID/EX，而下游前递窗口在排空，历史 bug 见 §3.6）；
2. **lane B 只允许结构上不产生控制流的指令**：`OP`/`OP-IMM`/`LUI`/`AUIPC`
   （第二级再放宽到 `LOAD`、`STORE`，见 §3.2）。这样 lane B **永远不会碰**
   重定向、陷阱、BHT/RAS、乘除单元——控制逻辑一个门都不加；
3. **同对无依赖**：`rd_a ∉ {rs1_b, rs2_b, rd_b}`（同拍没有 A→B 旁路），
   且 lane B 若要写寄存器则 `rd_b ≠ x0`（一条不写回的指令不配占用第二槽）；
4. **每对至多一条访存**（`!(p_mem_a && p_mem_b)`）——同对同拍锁存，
   于是任一拍 MEM 级至多一条访存，访存口一次 2 路 mux 就够，**不需要仲裁器**；
5. **不预测 taken 时才能配对**（`!p_pred_taken`）：被预测跳转的那条必须独占发射，
   否则到达级重定向与第二槽会在同一拍打架。

**收益。** 313,886 ← 363,515（引入双发射：每迭代周期数 **−13.7%**，效率 **+15.8%**）；
后续在双发射基础上叠加 EARLY_LD 与 lane B 访存，累计到 **217,088** 拍
（相对双发射刚落地时 −40.3%）。这是本项目单项收益最大的一处结构改动。

**代价（诚实上报）。** 可达频率 **91.40 → 87.00 MHz**（B1 前口径），
LUT **6,909 → 8,104**（含 RAS/BTB，见 §3.3；相对 A1 后基线 +58%）。
按赛题三项指标口径写清 **"1 升 2 降"**：执行效率升、Fmax 降、CoreMark/LUT 降；
我们要主动说明为什么仍然值得——赛题公式化简后 **主分 = CoreMark/MHz，主频与面积不进主分**，
而排序规则是"先比性能、性能相同再比面积"。

**验证。** 双发射的正确性判据不是"跑分变快"，而是**四条基线逐位不变**：
单发射档 `300,392` 拍、以及双发射档在每一次"接线在位但开关未关"的中间态都必须与
baseline 逐位一致（P2/P3 的关档判据都是这么立的）。四个子 CRC
`seedcrc 0xe9f5 / crclist 0xe714 / crcmatrix 0x1fd7 / crcstate 0x8e3a` 在全部配置
（单发射 / 双发射±EARLY_LD / ±Cache / ±lane B 访存）中**逐位一致**。

### 3.2 双发射的第二级：lane B 可访存（load → store）

**设计动机。** §3.1 的第二槽只放纯 ALU 指令时，`ld/st` 密集的循环里配对率被死死压住
——CoreMark 的链表中序遍历与状态机每几条指令就有一次访存。既然"每对至多一条访存"
已经把访存口简化成一次 2 路 mux，**"lane B 放访存"就只是把已有的访存口多接一条腿**，
不需要新的仲裁/握手。这一步分两个可独立关断的档（编译期 `parameter`）：

* `LANEB_MEM`：lane B 可放 **load**（默认 1，2026-10-16 交付档）；
* `LANEB_ST`：lane B 可放 **store**（A1，默认 1，**仿真已测 / 位流与上板待复核**）。

**lane B 放 load 的判据与代价。** load 在 lane B 时：
① 一律走**旧通路**（慢路径）——**不给它第二份提前读口**（EARLY_LD 的收益本身已在
lane A 上拿满，再复制一份读口/快照等于把最贵的时序链翻倍）；
② 它的 `rd` 参与 load-use 停顿的四个源比较（`rs1/rs2/rs1_b/rs2_b`），
且必须用"本拍真的会发射"（`if_id_pair`）门控，否则单发射下会误停（实测漏门控每迭代
多 9,906 拍）；
③ 未对齐判定只用地址低 2 位（`rs1_val_b[1:0] + imm_b[1:0]`），
把 32 位 `alu_result_b` 加法器锥从**取指关键路径**上摘掉——这一处是 P3.5 的
等价改写，也是"1 档能不能在 85 MHz 收敛"的关键。

**收益与代价（完整的"设计—收益—代价"链条，本项目最值得写的一段）。**

| 阶段 | 每迭代周期数 | 效率 (CoreMark/MHz) | 可达频率 | LUT |
|---|---|---|---|---|
| 双发射 + EARLY_LD + B1-RAS/BTB（0 档） | 229,597 | 4.3555 | 87.46 MHz | 7,663 (4.79%) |
| **+ lane B 放 load（1 档，`LANEB_MEM=1`）** | **217,088（−5.45%）** | **4.6064（+5.76%）** | 先掉到 **80.22 → 82.58 → 85.11** | 8,029 → **7,753 (4.85%)** |
| 钉住最优布局（`gplace_seed 5`） | 217,088（不变） | 4.6064 | **87.0549 MHz** | 7,753 |
| **+ lane B 放 store（A1，`LANEB_ST=1`）—— 实现并量化评估后未采纳** | **216,695（−0.181%）** | **4.6084（+0.043%）** | 7,889（+122，关档就已如此）| 83.8926（旧 seed 5，未重扫 ⇒ −0.43 ns）|

读法（这段是答辩要讲的）：
1. **P3 的翻开关先付出了时序代价**：关键路径变成
   `调色板 DRAM → lane B load 解包 → lane B ALU（`alu_result_b`）→ 未对齐判据 → 取指地址 → BRAM`，
   CPU 域 WNS 直接掉到 **−0.701 ns / Fmax 80.22 MHz**（85 MHz 生产档过不了闸门）。
   按盈亏平衡算（`delta` 实测）**break-even ≈ 80.37 MHz**，实测 80.22 ⇒ 物理分反而略亏，
   **所以当时交付档并没有换**——这是我们没有"看到 −5.45% 就冲上去交付"的原因。
2. **P3.5 用两处"严格等价"改写把频率还回来**：`b_addr_low` 改 2 位窄加法、
   `imem_addr2` 从 `fetch_addr[15:2]` 直接算（不再串在 `imem_addr` 之后）。
   两者都只改"用什么宽度/在哪一级算"，逐位等价可证，WNS **−0.345 → +0.014 ns**。
3. **P3.6 用布局把余量抬到可用**：40 个 place seed + 同一布局 8 个 route seed 全量取证，
   最优布局 **seed_5 = +0.277 ns / Fmax 87.0549 MHz**，用 `gplace_seed 5` 钉死复现。
4. **A1（lane B 放 store）**：把"lane B 可访存"补齐成对称的一对。改动面 6 处：
   配对白名单加 `STORE` 并新增 `p_b_rd_ok`（store 的 `instr[11:7]` 是 S 型立即数低 5 位、
   **不是 rd**，所以 `rd_b≠0`/`rd_a≠rd_b` 两条判据不能套在它身上——套上去会静默丢掉
   一大半可配对的 store）；"每对至多一条访存"由 `p_mem_a && p_mem_b`（`p_mem_b = ld_b || st_b`）
   完整表述；写口三条腿（`mem_we` / `mem_addr` / `mem_wdata`+`mem_byte_en`）各加一条 lane B 分支，
   且 lane B 必须**另存一份**存数据（lane A 复用 `ex_mem_wdata`，两者不同源）；
   未对齐 store 并进异常（`mcause=6`、`mtval=出错地址`、`mepc=lane B 的 PC`）；
   最后也是最关键的一处——`ld_bad_st` 必须并上 lane B 的 store：
   它与提前读口**同一沿**读写同址，漏了就退化成"store→load 快通路读旧值"的静默错值。
   **收益 216,695 拍（−393 = −0.181%）**，远小于立项时的 1~3% 预估——
   原因是 lane A 是访存时不能配对、且 store 在 CoreMark 里的可配对窗口本来就少；
   **实测数拍才是判据**（这也是我们坚持"先仿真数拍数、再评估"的原因）。

**"实施完成 ≠ 应当采纳"——A1 的处置过程（本节最想讲的一段）。**
A1 的功能判据、定向用例（含**反例对照**）、关档等价性全部通过，收益也确实是正的；
但它仍然**没有进交付配置**，理由是一条量化过的链条：

1. 净表 **LUT +122**（`7,767 → 7,889`，逻辑 LUT `7,195 → 7,317`；**FF 数完全相同 3,691**
   ⇒ 门控在寄存器层面确实折叠了），CoreMark/千 LUT 因此下降约 1.6%；
2. 更关键的是：**P3.6 用 40 个布局 seed 挣来的 +0.277 ns 余量，"钉"的是那一版净表**。
   我们做了对照实验——把 A1 改动 `git stash` 掉、用**原样 RTL 重跑同一流程同一 seed 5**，
   得到 **+0.277 ns / 失败端点 0 / 端点总数 19,114，与历史值逐位相同**（⇒ 流程是确定性的）；
   而 A1 版本（即使把开关关掉）在同一 seed 下是 **−0.156 ns / 5 个失败端点**。
   ⇒ **净表一动，"钉住的余量"就不复存在**——这不是流程抖动，是"新网表 + 旧种子"；
3. 于是换档有两条路：**要么降板上主频**（85 → 83 MHz；而计分公式化简后分数与主频成正比，
   **降频直接亏 2.4%，远大于 A1 的 +0.18%**），**要么重扫 40 个 seed**（数小时机时）再谈值不值。

**结论：保留实现、默认关闭、留档证据，不换交付档** —— 这与我们对 I/D Cache
（实现后量化评估，发现对分数贡献为 0）和 RV32A（关掉零性能代价）的处置是同一种判断。
反过来，这条经验也改写了我们对"参数门控"的表述：**"关档 ⇒ 行为逐位不变"在仿真层成立，
在综合层不成立**（LUT/时序会变），因此**任何 RTL 改动之后都必须重新核对时序余量，
不能沿用旧的定版数据**。

**验证（A1）。** `sim/tests/tb_laneb_st.S` 八个定向用例：字/字节/半字 store 的
写口三腿、相邻两条 store 必须不配对、lane A load + lane B store 必须不配对、
被冲刷的对里 lane B 的 store 绝不能写、未对齐 lane B store 的陷阱语义、
lane A 写回不被污染。**判据强度靠反例对照证明**：把 `ld_bad_st` 的 lane B 那一项
摘掉再跑同一套用例，用例 1 立刻 FAIL（读到旧值）⇒ 该用例确实有牙齿，
而不是"跑过了就算"。关档等价性：`LANEB_ST=0` 时 CoreMark **217,088 + 四 CRC 逐位不变**、
riscv-tests **49/1/0**、own_tests **7/0**；开档（=1）时 **216,695 + 四 CRC 逐位不变**、
riscv-tests **49/1/0**（唯一 FAIL 仍是 `ma_data` 哨兵）、own_tests **7/0**。

> **[!] 已知语义死角（主动写，别等评审问）**：lane B 的未对齐访存触发同步异常时，
   `mepc` 取的是 lane B 自己的 PC（肇事指令），而同拍 lane A 已被清掉；
   按"处理完跳过肇事指令（`mepc+=4`）"的常规写法，lane A 也就被跳过了。
   本设计两个交付固件都不产生未对齐访问（GCC `ilp32` ABI 保证），
   所以这条死角与 `ma_data` 一样属于"规范允许的取舍"，我们如实记录、不掩饰。

### 3.3 多层动态分支预测

控制流代价在五级流水里是纯损耗：一次误预测 = 冲刷 2~3 拍。我们的做法是**分层叠加、
每层只吃自己能吃干净的那部分**，并且**每层都用负向对照证明它真的承重**。

1. **ID 级静态后向预测 + `jal`**（最便宜的兜底）：条件分支偏移为负（后向）即预测跳转，
   无条件 `jal` 必跳。实测依据：CoreMark 计时区间内条件分支 53,173 条，后向 25,664 条里
   **90.8% taken**；前向 27,509 条里只有 6,101 条 taken ⇒ 静态规则已经拿掉大部分收益。
   目标只依赖 `pc+imm`，ID 级就齐备，而且**与 EX 级算出的目标必然相同**，
   不存在"方向对、目标错"的情形（这点让第一层不需要任何校验）。
2. **256 项带 tag 的 2 位饱和计数器 BHT**（只预测条件分支方向），索引 `PC[9:2]`、
   tag `PC[31:8]`，直接映射。它只多拿约 1%（那 6,101 条前向 taken 中的一部分），
   代价是 PC 索引表 + 若干流水线标志位。**查询点从 ID 级挪到"到达级"**：
   同一拍 BRAM 已给出指令字，可当场算目标并立即重定向，被预测 taken 的分支因此
   少付 1 拍取指重定向气泡。
3. **16 项返回地址栈 RAS**：`ret`（`jalr x0,0(x1|x5)`）是调用密集代码里最贵的一类跳转，
   而它的目标依赖 `rs1`、ID 级没有前递通路 ⇒ 以前必须等 EX 级冲刷。RAS 让 `ret` 在
   **到达级**直接拿栈顶当预测目标并同拍重定向；push 在 EX 级（call 提交那拍写 `pc+4`）。
   收益 **232,345 → 229,597 拍（−1.18%）**，且 `region commit`（真正提交的指令数）
   **逐位不变** ⇒ 收益纯粹来自气泡减少，不是"少执行了指令"。
   实测 8 项与 16 项栈的命中率都是 **99.93%**（CoreMark），取 16 是为 RT-Thread 那种更深的嵌套。
4. **256 项直接映射 BTB**（赛题点名的"动态分支预测器"）：只给**间接跳转 `jalr`**
   预测目标（条件分支/`jal` 的目标由到达级现算即正确，BTB 不与 BHT 抢方向）。
   优先级 **RAS > BTB > PC+imm**，且目标只折进**已有的** `p_target` mux 腿，
   **绝不新增 `fetch_addr` 的腿**（取指地址 mux 的每一级都是 Fmax 第一风险点）。
   BTB 命中即让该 `jalr` 独占发射（`pair_now=0`），与它"不被预测时的行为"一致。
   **对效率口径逐位中性**（CoreMark 的 `jalr` 几乎全是 `ret`、已被 RAS 捕获，
   BTB 触发极少且不在计时区）⇒ 我们不把它写进"优化闭环"表（写进去反而误导），
   它的价值在**功能完整性 + 赛题点名项**。

**"用负向对照证明承重"这件事值得单独说。** 预测目标（RAS 的栈顶、BTB 里的目标）是
**绝对地址猜测**，猜错必须能纠正——所以 §3.3 的校验条件是：被预测的指令在 EX 级
拿真实目标与 `id_ex_pred_target` 比对，**不符即并入冲刷**。功能正确性由它兜底；
而"CoreMark 逐位不变"只能证明**没算错**，证明不了**预测有效**。
于是我们另给两条独立证据：① `sim/tests/btb_indirect.S` 定向构造间接跳转
（函数指针表）验证目标预测与纠正；② `+JALRTRACE` 探针逐条流出
`{类型, pc, 目标, rd, rs1}`，离线用 RAS 模型复算命中率（99.93%）。
**残差**我们也写清：`jalr` 的别名冲突 149/341 次（表只有 256 项），
扩表预期 **+1%**，列入后续工作（§8）。

**代价。** RAS+BTB 合计 LUT **7,482 → 8,104（+622）**，CPU 域余量
**+0.311 → +0.034 ns**（仍为正但薄）；后续砍掉 RV32A 后回到 **+0.330 ns**，余量问题缓解。

### 3.4 load 地址提前与"快通路"（EARLY_LD）

**设计动机。** 计时区间里 load-use 停顿原本占 **10.4%（27,181 拍）**：
load 的地址在 EX 级才算、数据 WB 才回来，紧跟其后的消费者必须停一拍。

**做法。** 把 load 的地址计算**提前到 ID 级**，并用**专用第三个只读端口**（同步读 1 拍）
在"该 load 的 EX 级"就把数据取回来 ⇒ 消费者在 EX 级即可前递到数据，停顿消失。

**判据（哪些 load 能走快通路——"判据先行"是这里的核心）。** 只有同时满足四条的 load 才走：
① 基址寄存器在 ID 级拿得到（不是"EX 级那条指令刚写"、也不是"EX/MEM 里是 load/AMO"）；
② 地址落在 RAM 段（提前读口只镜像 RAM）；③ **紧前一对里没有 store**（与提前读口同址时是
同一沿读/写，会读到旧值）；④ 前/后没有 AMO。**四条都是保守判据：判错只是退回旧通路
（慢一拍，但一定对）**，这条性质让整个优化不可能引入功能错误。
实测可用率 **86.3%**（被挡住的只有 696 条基址在 EX + 1,869 条紧前是 store + 48 条非 RAM）。

**收益与代价。** 313,886 → **241,633 拍（−23.0%）**。代价是三条硬约束下的**零寄存器**读通路
（见 §3.7）与一处很贵的前递 mux（2026-10-11 综合实测：多一级 mux 时它一度成为 CPU 域最差路径）。
**这一处正好是"功能修复 ≠ 能塞进主频"的教科书案例**（`mem_ready_int` 门控那种极晚的使能信号
每加一级 AND 都要重新量时序），我们把这条经验写进了验证章（第 5 章）。

**这一节还有一个"由我们的新改动触发、并且原地闭环"的例子**：A1 让 lane B 也能放 store 之后，
判据 ③ 的"紧前一条"就变成了"紧前一对里的**任一** lane"，`ld_bad_st` 必须从
`id_ex_mem_write` 扩成 `id_ex_mem_write || id_ex_b_mem_write`——**设计面一变，
判据面必须同步重算**，这就是我们在 §3.2 坚持"反例对照"的原因。

### 3.5 取指时序契约与停顿补偿（深水区）

取指口对外是一份**契约**而不是一堆连线：同步读、**恰好 1 拍延迟**（第 T 拍给地址、
第 T+1 拍出数据）、只读、**不做任何仲裁/冲突检测**。整个流水线的停顿/冲刷补偿都建立在这份
契约上，因此它是"承重墙"，改它必须先改契约本身。

**稳态不变量与停顿补偿。** 稳态下 `imem_rd ≡ mem[pc_r − 4]`；而**停顿补偿不是让 `pc_r` 后退**，
而是**把发出的取指地址退回在途指令地址 `if_addr_d`**（同步读重新锁存同一字）。
这一点必须写清"为什么不能那么做"：连续停顿下 `pc_r` 后退会让**非幂等指令被重复执行**
（这是历史 bug）。跳转重定向的 `+4` 同理：目标是"已经发出的地址"的函数，不是 `pc_r` 的函数。
另一处同源细节：第二取指地址 `imem_addr2` 从 `fetch_addr[15:2] + 1` 直接算，
**不能**写成 `imem_addr + 1`（后者把一条 14 位加法串在关键路径上，
P3.5 实测尾段多出 `0.299+0.157+1.166 ns`；两式逐位等价，改写只是把自由度还给综合器）。

**"冻结拍"这个隐藏状态机（本项目最贵的一课）。** 当访存未就绪（`mem_ready_int=0`，
带 Cache 或 `+MEMWAIT` 时出现）时整条流水线【保持】。但"只该发生一次"的 EX 级副作用
各有各的写法，凡与"离开 EX"不同源的都会在冻结期间**提前或重复施加**：
级间寄存器的**清零**、**CSR 写**、`mret` 的 `mstatus`、乘/除单元的**使能**。
它们都是静默错值，而且**只在有停顿的配置下暴露**（四条常规基线全盖不住）。
判据统一为：**这些副作用一律与"离开 EX"同拍提交**（即都门控 `mem_ready_int`），
`trap` 是唯一例外（无条件，肇事指令必须死）。这条纪律的完整证据链
（`csrrw sp,mscratch,sp` 撞上冻结 ⇒ 中断跑在线程栈 ⇒ 踩坏内核链表）
写在第 5 章"验证体系"里，它是我们**用大固件（RT-Thread + 五子棋）作照妖镜**
才抓到的一类缺陷。

### 3.6 多拍除法器与 II=1 乘法器

**除法器（恢复余数法，多拍）**：关键路径 ≈ 一个减法器。若用单拍组合除法，
它会把 32 位除法链并进 EX 级最差路径，直接吃掉主频——我们明确选择"多拍换频率"。
流水线侧只需一条 `mc_stall`（EX 级多拍单元占位）与配套的清/保持门控。

**乘法器（II=1 流水线化的两拍单元）**：单拍组合乘法在综合报告里占关键路径
**10.05 ns（整条数据通路的 56%）**，且路径起点是 BRAM（"`lw` 紧跟 `mul`"要把访存数据
在一周期内穿过解包、前递、4 级 APM 乘法链）。摘出来单独占两拍后它不再落在关键路径上。
代价与精算：每条 `mul` 多 1 拍，而计时区间内实测有 **9,396 条 `mul`**（必须实测，
静态推算会小 5.8 倍），于是 354,119 → 363,515 拍。
随后我们把乘法器做成 **II=1**（`en` 与流水线同源、每拍都能收一条）并把 "load-use 式停顿"
**收窄到只剩"紧邻消费者"**：实测 9,396 条 `mul` 里只有 **108 条**后面紧跟消费者，
于是"每条 mul 都停 1 拍"变成"只有 108 条停 1 拍" ⇒ 241,633 → **232,345**（−9,288 拍，与
`9,396 − 108 = 9,288` 逐拍吻合——**这条吻合本身就是"改动真的只做了这一件事"的证据**）。
**这里的关键纪律**：多拍单元的使能必须与 EX/MEM、MEM/WB 同源（`mem_ready_int`），
否则访存停顿期间乘法器自己前进、`*_is_mul` 却保持，写回值会错位（`+MEMWAIT=3` 抓到的坑）。

### 3.7 前递路径优先级与写通路零寄存器

**前递优先级**（同一级内"年轻的赢"）：
`EX/MEM(lane B) > EX/MEM(lane A) > MEM/WB(lane B) > MEM/WB(lane A) > 寄存器堆`。
两条硬规则：
* **load 的结果不从前递取**（`wb_sel=01` 时 EX/MEM 里是**地址**不是数据）——
  lane B 若也是 load，同一条规则必须扩展到它的四个前递项（漏一处就是
  "把地址当数据前递"的静默错值）；
* 快通路 load 的**解包后**数据要另走一路（`lb/lbu/lh/lhu` 要按 `funct3` 与地址低两位
  取字节/半字）：只前递原始字时 `lw` 全过、`lb/lh` 全 FAIL（`lhu` 还可能因为测试数据
  高半字为 0 而蒙混），CoreMark 的 `matrix`/`state` CRC 也会全错（它用 u16）。

**写通路零寄存器**：`mem_addr / mem_wdata / mem_byte_en / mem_we` 必须是 MEM 级的
**组合输出**，一拍内直接进总线（SB/SH/SW 的字节复制留在核内——那是指令语义，总线不该懂）。
在写通路里插一级寄存器会得到"存完立刻读回读到旧值"（`st_ld`/`ld_st` 直接 FAIL）。
配套的是读侧的对称约定：**读数据与读选择位在 MEM→WB 沿寄存**，所有地址源统一 1 拍延迟、
**不搞特例**——"哪里能插寄存器、哪里不能"就是靠这两条划出来的。

### 3.8 RV32A（AMO/LR/SC）的可配置取舍

AMO 由独立多拍单元实现（读-改-写 + `LR/SC` 预约），占 MEM 级期间用 `amo_hold` 把
`mem_ready` 压 0（EX/MEM 是**保持**而不是被清，否则读-改-写被拦腰截断），
并要求 `!amo_hold` 门控中断（否则 AMO 中途被清会丢写回）。

**它默认关（`A_EXT=0`），理由是量化的**：赛题公式化简后主分是 CoreMark/MHz，
而两个交付固件（CoreMark 用 `-march=rv32im_zicsr`、RT-Thread 档实测 ELF 里 0 条原子指令，
原子由软件实现）**都不含原子指令** ⇒ 关掉**零性能代价**，换来 **−441 LUT**
与 **+0.296 ns** 余量（CPU 域 `+0.034 → +0.330 ns`）。
验证口径不丢：`-DAEXT` 保留 A 扩展的整核测试与 RT-Thread `-Atomic` 配置，
`sim/tests/tb_amo_cpu.S` 端到端覆盖 AMO/LR/SC。
**这是"高阶任务①的实现保留、但对交付配置做量化取舍"的典型写法**——
我们不假装它在生产档里生效，也不因为"不做"而删掉实现。

## 第 6 章 性能分析

本章只回答四个问题：**分数怎么来的（口径）→ 周期花在哪（构成）→ 每一处改动值多少（闭环）→
代价与代价的边界在哪（三口径 + 折衷判据）**。所有数字取
`论文框架 §0.1` 的提交档口径；**板上数与仿真数分开标注**（同一条 RTL、同一个布局，
但计时区间边界不同 ⇒ 板上 `Total ticks ÷ ITER` 会略小于仿真 `region cycles`：
**217,036.1 vs 217,088**，两者都必须给，不许只挑好看的那个）。

### 6.1 CoreMark 口径推导（自证，不是"随便填个 ITER"）

赛题的计分公式是 `Score = Iterations / (Total_Time × Frequency)`。把 `Total_Time` 用
`Total_ticks / Frequency` 展开即得

> **`Score = Iterations / Total_ticks = 1 / (每迭代周期数)`（单位：CoreMark/MHz）**

两边同乘时钟只改变量纲，**所以主分"执行效率"= CoreMark/MHz 与主频无关**。
`Iterations`（Iterator 规模）必须**跟时钟与每迭代拍数一起走**：`Total_Time` 要落在
10 s 量级才有效，提频会让旧 `ITER` 的运行时间跌破 10 s 而被判 invalid
（27→45 MHz 时旧 `ITER` 只剩 6.54 s，我们正是踩过这个坑才改成
"先量每迭代拍数、再按目标频率反解 `ITER`"）。提交档 `ITER=4332`、
`Total ticks 940,200,316`、`Total_Time 11.0605 s`。

另有两个必须主动说明的口径雷区：`Total time (secs)` 是**整数截断**（`HAS_FLOAT=0`，
日志里的 `11` 实际是 11.0605 s）；`Iterations/Sec` 是按截断后的秒数算的
（日志里的数不是得分），**真实得分以我们复算的为准**。

**【表 5：周期构成】**（两个口径，缺一不可）：

**Fmax 降**（91.40 → 87.0549 MHz，−4.75%）、**CoreMark/千 LUT 降**（LUT +12.2%、分数 +11.3%）。
按新公式 `Score = Iterations/(Total_Time × Frequency)` 化简后**主分只看执行效率**
⇒ 这个折衷在主分上**净赚 +11.3%**；代价落在指标(2)Fmax 与指标(3)CoreMark/LUTs 上，
而排序规则是"**先比性能、性能相同再比面积**"。**我们不把这笔账说成"全面更优"**——
它就是一笔有明确代价的交换，换得值不值可以逐项核对。

### 6.4 频率-效率折衷的定量判据与布局取证

**折衷不是拍脑袋，是先算盈亏平衡点再动手。** P3 的 1 档在逻辑上明确收益（−5.45% 拍），
但一次综合就把 CPU 域余量打到 **−0.701 ns / Fmax 80.22 MHz**。按
`效率收益 ÷ 频率损失` 的盈亏平衡频率 ≈ **80.37 MHz**，而实测只有 80.22 MHz
⇒ **物理分反而略亏**，**所以当时我们按兵不动、没有换交付档**。
随后用两处**严格等价**改写（§3.2 第 2 条）把那条腿从取指路径上摘掉，余量回到
**+0.014 ns**，再用**布局**抬到 **+0.277 ns** ⇒ 折衷才真正成立。

**布局取证（这是本项目"工程过程"含金量最高的一段）：** 40 个 place seed + 同一布局下
8 个 route seed **全量跑完并逐 seed 读 CPU 域**（不是读 PDS 默认排序的"全设计最差"
——那个排序会把跨域 `CPU→pix_clk` 的既有伪影算进来，**4 批默认分别挑到
+0.014 / +0.166 / −0.111 / −0.091 ns，后两批时序根本不过**）。
最终最优布局 **seed_5 = +0.277 ns / Fmax 87.0549 MHz**，用
`(_option gplace_seed (_integer 5))` **钉死复现**，跑分档与演示档**两颗位流同布局**
（"1 档统一定版"）。**这条经验也写进论文**：单 seed 钉定时 P&R 阶段不出 `.rtr`，
时序必须从后置 `report_timing` 收——**流程细节本身就是复现性的证据**。

### 6.5 剩余空间与下一步（与第 8 章呼应）

按"边际收益 ÷ 风险"排序：**① BTB 表扩容 256→1024/4096**（`jalr` 别名冲突 149/341 次，
预期 **+1%**，代价是 LUT 与 `fetch_addr` 无新腿 ⇒ 优先）；
**② 摘掉 1.76 ns 的跨模块"投放线"**（lane B load 数据源打一拍；
代价是访存延迟 +1 拍 ⇒ 每迭代拍数要**重测**、三处口径同步）——这是指标(2)唯一
确定性较高的收益点；**③ 配对率扩展**（先仿真统计"因规则被拒的相邻对"占比，再逐条放宽，
每条都要等价性论证）。**明确不做**：定向窄 region 框选（上限仅 +0.02~0.05 ns，
且大区域已有确定性负面前科）。

> **[!] 2026-10-16 实测修订（草稿期就改，别留错话）**：上面 ①③ 两条后来都被实测否证 ——
> ① BTB **扩表对捕获率无影响**（`+JALRTRACE` 实测 `jalr` 1,374 条 **100% 是函数返回**、
> 直接映射 BTB 在 16~16384 项下捕获率恒 **6.40%**：不是冲突，是"单点位自己就有 8 个目标"；
> 正解是 **RAS，8 项即 99.93%**，已进交付档）；BHT 256→1024 实测只值 **+0.10% 并已回退**。
> ③ 配对率这边：`2026-10-15` 的静态复放分析证明"分支配对"**早已实现**，且
> **周期侧唯一剩下的门 = 给 lane B 访存能力（上界 +7.46%）**；其中 lane B load 已进交付档
> （效率 **+5.76%**），lane B store 实测 **+0.181%**（模型给 +0.43%）⇒ **配对率这条线已经走完**。
> ⇒ 效率侧目前**没有已知的可观余量**；唯一还开着的 CPU 项是 ② 的那条 Fmax 路径，
> 而它有一个关键性质：**它只被"访存落在视频窗口"的 load 走到，而 CoreMark 全程不碰视频窗口**
> ⇒ 把视频窗口读做成"多压一拍 `mem_ready`"**对上板分数零周期代价**，
> 只影响演示固件读视频窗口的少数访问 —— 这是"效率优先"下少见的两头都占的项。

## 第 5 章 验证方法与结果

处理器验证的难点不在"跑通一个测试"，而在**判据本身的强度**：跑分变快可能只是少执行了指令；
`49/50` 里那一个 FAIL 可能是真缺陷、也可能是规范允许的二选一；
一次"没报错"可能只是因为**那个错误只在有停顿的配置下才会暴露**。
本章按"证据强度"组织：先讲三层验证体系与五条回归纪律（方法），
再用**六个真实案例**说明这些判据各自抓到过什么（结果），最后给板级证据链与未覆盖项清单。

### 5.1 三层（+板级）验证体系

| 层 | 载体 | 判据（可引用） |
|---|---|---|
| **① 模块级** | `sim/tools/` 下各单元 testbench（ALU / 乘除 / 前递 / CSR / 取指握手 / AMO / 总线） | 每个多拍单元的直接读写激励 + 边界值；改一处单元先跑它 |
| **② 整核指令级** | `riscv-tests` **49 PASS / 1 FAIL(`ma_data`) / 0 TIMEOUT**（`sim/tb_riscv.v`）+ 自写定向 `own_tests` **6/0**（双发射 R1/R2/R5 用例、AMO、异常/中断、Cache corner） | 每一条 FAIL 都有归因文档；`+MEMWAIT=1/2/3` 与 `DCACHE/ICACHE` 组合各自单独过一遍 |
| **③ 系统级** | CoreMark（**四 CRC 逐位** + `region` 自证）、RT-Thread 四配置、五子棋端到端 | CoreMark 的 `Total ticks` **必须等于** `+PROF` 的 `region cycles`；四 CRC `e9f5/e714/1fd7/8e3a` 与基线逐位一致；五子棋仿真 **6/6 checks** |
| **④ 板级** | 紫光同创 PG2L200H + HDMI + 真按键 | 跑分：`Total ticks 940,200,316`（= 11.0605 s，ITER=4332）⇒ **391.66**，四 CRC 与仿真一致；演示：banner `RTL=0x20261027`、render/AI 两条线程、`[hb] 5000→50000` 无断、**真按键下完一局判出 `WHITE wins`**、`D18` 常亮 |

三层之间是**互证**关系，不是"跑一遍就算过"：② 保证 ISA 语义，③ 保证长序列/编译产物/Cache 行为，
④ 保证物理实现（时序、上电、外设、显示器）。**只有②③④同时绿**才算一个配置过关。

### 5.2 五条回归纪律（"过程可复现"的证据）

1. **四组并列基线**：回归不认"单一数字"，而是**四组指纹同时成立**
   （默认档 / `EARLY_LD=0` / 单发射 / Cache corner）。每组各有自己的每迭代周期数，
   **改一处必须四组都量** —— 很多"看起来只影响性能"的改动都是在这一步露出功能变化。
2. **"接线在位、开关未翻"等价性**：新能力先只做接线（编译期 `parameter` 默认关），
   判据是**四组基线逐位不变**；再翻开关拿收益。lane B 访存的 load 与 store 两级都是这么落地的
   （`LANEB_ST=0` 时 CoreMark **217,088** + 四 CRC **逐位不变**）。
   **[!] 这条纪律的边界（2026-10-16 实测补充）**：它**只在仿真层成立** ——
   关档源码在综合后仍带来 LUT 与时序差异（同一 `gplace_seed` 下逻辑 LUT **+122**、
   CPU 域余量 **+0.277 → −0.156 ns**），所以**"关档 ⇒ 回到旧网表"不成立**：
   任何 RTL 改动之后都必须**重跑一次综合核对时序余量**，不能沿用旧定版数据。
3. **探针自证**：性能类结论不许只靠推算。我们给 `+PROF`（拍数分类分解）、
   `+PAIRTRACE`（到达级配对流）、`+JALRTRACE`（`jalr` 类型/目标，离线 RAS 模型复算命中率）、
   `+AGU_PROBE`（AGU 级数与 Δns）四类探针；**探针口径与日志首行自证**
   （`SIM CONFIG: DUAL_ISSUE=1 … LANEB_MEM=1 LANEB_ST=0`）写进每份日志第一行。
4. **反例对照（判断"用例有没有牙齿"）**：新增判据后，**故意把判据摘掉再跑一遍**，
   确认用例会 FAIL。lane B 的 store→load 快通路就是这么验的：摘掉 `ld_bad_st` 的 lane B 项后，
   定向用例 1 立刻读到旧值 ⇒ 用例有效，且反证 store 真的落在 lane B 上。
5. **日志留证**：每个结论都指向"可打开的原始文本"（串口日志带时间戳、仿真日志首行自证配置）。
   位流一律给 **md5 + 来源报告 + 上板时间**三件套，并明确 **md5 不是布局指纹**
   （同一布局的两次构建 md5 不同）。

### 5.3 六个案例：这些判据各自抓到过什么

> 入选标准是"没有这套判据就会漏掉"。这一节比罗列测试清单更有说服力。

**(1) `fence_i` TIMEOUT：根因是存储器结构，不是"少实现一条指令"。**
哈佛结构（独立 I/D 存储器）下自修改代码无法生效 ⇒ `riscv-tests` 的 `fence_i` 直接 TIMEOUT。
改成**统一存储器 + 双端口 BRAM**（取指口 A / 访存口 B）后，**回归清单里唯一变化的就是这一项**
（TIMEOUT → PASS），而 **CoreMark 周期一字不差**。⇒ 一次功能修复若"不改变性能指纹"，
才是它没有副作用的最强证据。

**(2) 冻结拍的隐藏状态机：EX 级"只该发生一次"的副作用必须在离开 EX 那拍提交。**
访存未就绪（`mem_ready_int=0`，带 Cache 或 `+MEMWAIT` 时出现）时整条流水线保持，
而级间寄存器清零、CSR 写、`mret` 的 `mstatus`、乘除单元使能这些副作用若与"离开 EX"不同源，
就会在冻结期间**提前或重复施加**。最典型的一次是 `csrrw sp,mscratch,sp` 撞上冻结拍：
中断在 `sp` 换栈**之前**被取走 ⇒ 中断跑在线程栈上 ⇒ **踩坏内核链表**（表现为随机死机）。
统一判据：**副作用一律门控 `mem_ready_int`，`trap` 是唯一例外（肇事指令必须死）**。
⇒ 这类缺陷**只在有停顿的配置下暴露**，四条常规基线全盖不住 ——
**真正的照妖镜是"大固件 + 有停顿的配置"（RT-Thread + `+MEMWAIT`）**，而不是更小的单元测试。

**(3) 快通路 load 的"解包"，以及"功能修复 ≠ 能塞进主频"。**
EARLY_LD 的提前读口只前递**原始字**时，`lw` 全过、`lb/lh` 全 FAIL，而 `lhu` 还可能因为测试数据
高半字为 0 而蒙混；改成按 `funct3` 与地址低两位解包后，`matrix`/`state` 两个 CRC（用 `u16`）才对上。
更值得写的是它的**下一跳**：这个修复插在一条极晚的使能信号（`mem_ready_int`）后面，
**每加一级 AND 都要重新量时序** —— 综合实测它一度成为 CPU 域最差路径。
⇒ **"改对了"与"能塞进主频"是两件事**，必须分开证明。

**(4) lane B 访存的陷阱语义与一条已知死角。**
lane B 的未对齐访存触发同步异常时，`mepc` 取**肇事指令自己的 PC**（`trap_from_b`），
配合"跳过肇事指令"的常规写法（`mepc += 4`）即可正确恢复；同时 trap 会清 ID/EX 与 EX/MEM
⇒ **"既陷异常又改了内存"不可能发生**。**主动记下的死角**：同拍 lane A 也随该对被清，
于是"跳过 lane B 的肇事指令"同时也跳过了 lane A（我们约定它是幂等填充指令，无副作用）。
两个交付固件（GCC `ilp32`）都不产生未对齐访问，故该死角与 `ma_data` 同属**规范允许的取舍**。

**(5) A1 的反例对照**：见 §5.2 第 4 条与 §3.2 —— 它是"新判据必须自证有牙齿"的完整实例。

**(6) `ma_data`：49/50 是一次主动取舍，不是遗留缺陷。**
`riscv-tests` 的 `ma_data` 检验"未对齐访存是否精确陷阱"。规范允许两种实现
（陷阱 / 由硬件完成跨字访问），我们选择**精确陷阱 + 精确 `mtval`**（唯一 FAIL 即此项，
`testnum 668`），理由是软件栈语义更可预期（`mtval` 可诊断），并且**不通过"放宽测试"去换好看的 49/50**
—— 论文与答辩都按"**49 PASS / 1 已知取舍**"表述。

**性能类结论同样有独立旁证**（不靠单一数字）：
* 周期构成用 `+PROF` 实测：单发射口径提交 288,056 拍（**79.2%**）、分支 **45,343（12.5%）**、
  load-use **20,720（5.7%）**、乘法 **9,396（2.6%）**；另一口径 `noretire 17,642（7.59%）`
  ≈ 分支 5,645 + load-use 6,171 + 残余 2,731。**两张表交叉成立**才敢说"哪一块是瓶颈"。
* EARLY_LD 可用率 **86.3%**（被挡：基址在 EX 696 / 紧前是 store 1,869 / 非 RAM 48）；
  RAS 命中率 **99.93%**（8 项与 16 项同值 ⇒ 不是"靠表大"换来的）。
* I/D Cache 实测命中率 **I 98.985% / D 99.929%**，但周期口径**没有收益**
  （后端是单周期 BRAM：命中零收益、缺失 2 拍纯亏）⇒ **它的价值在功能条目、不在分数**；
  这个"实现并量化后判定"的闭环比"做了 Cache"本身更能说明工程判断力。

### 5.5 未覆盖项（主动清单，比被问出来强）

1. **外部中断 `MEIP` 无端到端测试**：不承诺（`mtip` 经 CLINT 已有覆盖）；
2. **`mtime` 32 位在 ~50.5 s 回绕**：tick 写法已规避，长跑 uptime 需软件层处理；
3. **自修改代码的窗口性质**：无 I-Cache 的简单核固有性质（改写"取指窗口内"的指令），
   `riscv-tests` 未覆盖，我们只保证 `fence_i` 语义；
4. **总线无 `ready` 握手**（固定延迟契约）：接慢速外设需升级，已论证写入后续工作；
5. **`ma_data` 与 lane B 未对齐访存的语义死角**（§5.3(4)(6)）——规范允许，但不掩饰；
6. **PDS 选种口径**：多 seed 模式按"全设计最差"排序（含跨域既有伪影），会挑错布局
   ⇒ 已固定为"**逐 seed 读 CPU 域再钉 `gplace_seed`**"的流程（§6.4），
   并把"`gplace_seed` 只对某一版净表成立"写进纪律（§5.2 第 2 条的边界）。
