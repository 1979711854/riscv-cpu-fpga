### 2.2 任务 B：补一条「代码 > 32 KB」的取指测试

**为什么非有不可**：64 KB 扩容的**全部意义**就是让程序能大过 32 KB，而现有
**每一个**程序都远小于它（CoreMark 14,348 B / 裸机五子棋 11,528 B /
RT-Thread 版 25,484 B）。后果就是 `imem_addr2` 漏改宽度（13 位 vs 14 位）→
取指地址 ≥ `0x8000` 时**双发射的第二条指令从低 32 KB 取错地方** → 这条 bug
躲过了全部四条基线，是**读代码读出来的**，不是测出来的。
修是修了（commit `f72ef25`），**但通路仍然零覆盖**。

**做法：不改链接脚本。** 运行时把一段代码**拷贝到高地址**再跳过去执行：
拷贝 → `fence.i` → `jalr` → 回来校验。这样不用给 `sim/tests/` 引入新链接脚本，
也不用动所有自写测试共用的 `scripts/riscv_tests_link.ld`。

#### [重点] 怎么让这个测试**真的能检出**那个 bug

这是唯一有技术难度的地方，**不做这一步测试就是恒真的**。

故障机理：取指 word `W`（≥ 8192）时，被截位的 `imem_addr2` 读的是
word `W + 1 − 8192`。所以在**低地址**放"毒药"即可。

但**光放毒药没用** —— `core.v` 的配对判据是门控的：

```verilog
assign pair_now = (DUAL_ISSUE != 0) &&
                  (imem_rd != 32'd0) && (imem_rd2 != 32'd0) && !p_pred_taken &&
                  !p_muldiv_a && !p_amo_a &&
                  p_opcode_b_ok && (p_f7_b != 7'b0000001) && (p_rd_b != 5'd0) &&
                  (p_rd_a != p_rs1_b) && (p_rd_a != p_rs2_b) && (p_rd_a != p_rd_b);
```

`p_opcode_b_ok` 只放 `OP(0110011)` / `OP-IMM(0010011)` / `LUI(0110111)` /
`AUIPC(0010111)`。**毒药写成 `unimp` 或全 0 都不行**：前者配不上对、
后者被 `imem_rd2 != 0` 挡掉 —— 两种情况下 lane B 都不发射，
表现只是"退化成单发射"，**测不出错**。

**一个验证过的设计**：

- **低地址毒药块**：`addi s0, s0, 1` 重复 N 次（`s0` 只在毒药里被写）
- **高地址执行块**：`addi t2, t2, 1` 重复 N 次
- 校验：**`s0 == 0` 且 `t2 == N`**

| | 配对判据 | 结果 |
|---|---|---|
| **修复后**（lane B 取到真正的下一条 `addi t2,t2,1`）| `p_rd_a(t2) != p_rs1_b(t2)` **不成立** → 不配对 | 单发射执行：`t2` 加 N 次，**`s0` = 0** |
| **截位时**（lane B 取到毒药 `addi s0,s0,1`）| `t2 != s0`、`t2 != x0` → **配对成立** | lane B 执行毒药 → **`s0` != 0** |

即 **`s0 != 0` 就是"截位 bug 存在"的判据**，不用看波形。

**地址映射**：执行块放 `D`、毒药放 `P`，要满足 `D + i + 1 − 8192 = P + i`，
即 **`D = 8191 + P`**。`P` 用 `la` 在**运行时**算出来（别写死 ——
环境宏的序言长度会变），再换算成字节地址作为拷贝目标。

**验收**：
- 修复后：新测试 **PASS**（双发射与单发射都跑）
- **[关键] 回归验证**：把 `rtl/core/core.v` 的 `imem_addr2` 临时改回 `[12:0]`、
  `+ 14'd1` 改回 `+ 13'd1`（`cpu_top.v` / `mem_bus.v` 的宽度也要跟着窄），
  **新测试必须 FAIL**。验完改回来。
  > 提示：宽度检查会先拦下你（约定 40，那是**预期的**）。
  > 想验证功能就临时注释掉 `run_own_tests.ps1` 里那段检查，或手工
  > `iverilog`+`vvp` 绕开脚本。**验完记得恢复。**

**坑**：`fence.i` 必须写；拷贝目标不能碰到 `0xFFF0~0xFFFF`（CoreMark 兼容区）；
别用 `sp`；建议文件名 `sim/tests/hi_fetch.S`，加完更新 `run_own_tests.ps1`
第 41–46 行注释里的清单。

## 3. 纪律与命令

```powershell
# 开工（不需要板子）
scripts\gomoku\run_test.ps1      # 270 项单测 + RV32 交叉编译零警告检查
scripts\gomoku\play.ps1          # PC 端对弈（-Easy / -Normal / -Hard / -White）
scripts\gomoku\run_sim.ps1       # 端到端仿真（真 CPU + 真 PPU）

# 改 RTL 必跑（数字必须逐位不变）
scripts\run_riscv_tests.ps1                 # 双发射：49 PASS / 1 FAIL / 0 TIMEOUT
scripts\run_riscv_tests.ps1 -Single         # 单发射：同上
scripts\run_own_tests.ps1                   # 自写测试（异常/中断）
scripts\run_coremark.ps1 -Iter 1            # Total ticks = 313,886
scripts\run_coremark.ps1 -Iter 1 -Single    # Total ticks = 363,515
```

1. **跑 CoreMark 时会打印 `ERROR! Must execute for at least 10 secs...` 和
   `Errors detected` —— 那是 ITER=1 的正常现象，不是失败。**
   判据是 **`Total ticks`** 和四个 CRC（`seedcrc`/`crclist`/`crcmatrix`/`crcstate`）。
   **`crcfinal` 不比** —— 它是跨迭代累加器，必然随 ITER 变（约定 29）。
2. **iverilog 的「端口宽度不一致」警告是硬错误**（约定 40）。看到脚本报
   `expects N bit(s), given M`，**别改脚本，去把宽度对齐**。
3. **改 RTL 就要重新综合、重新上板**（约定 23），且**综合前要改
   `rtl/core/csr_file.v` 的 `DESIGN_REV`**（约定 42）—— 固件会把它打在串口
   第一行（`[build] FW=... RTL=0x...`），日志靠它自证是哪一版网表。
4. **改固件后 `mem.hex` 行数会变，`build_bitstream.ps1` 的守卫会拦你** ——
   **那是守卫在工作**，实测后更新 `expectLines`，别急着放宽。
5. **动 `scripts/gomoku/` 就够了吗？** 大多数时候是（五子棋是纯固件）。
   但**任务 A（vblank）第 2 条要改 `rtl/video/`**，那要走 RTL 全量回归。
6. **提交按里程碑拆、信息写清改动；不自动 push。**
