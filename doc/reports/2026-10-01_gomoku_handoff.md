## 2. 怎么跑（四条路径，按"离硬件多远"排）

### 2.1 在 PC 终端里跟 AI 下棋（最快，1 分钟）

```powershell
scripts\gomoku\play.ps1              # 你执黑先手，AI 用 NORMAL(4层)
scripts\gomoku\play.ps1 -Hard        # AI 用 HARD(6层)
scripts\gomoku\play.ps1 -Easy -White # AI 用 EASY，你执白后手
```

落子输入 `H8`（列字母 A–O + 行号 1–15，`H8` 就是正中天元），也接受 `7 7`。
命令：`q` 退出　`n` 重开　`u` 悔一步　`+` 加难度　`-` 降难度　`h` 帮助

每步 AI 走完会打印 **节点数 / 实际深度 / 耗时(ms) / 评分** —— 这四个数是时间预算的判据。

> [!] **命令都是单个字符。** 别设计"字母+参数"的命令 —— 列字母是 A–O，`L2` 既是
> 「L 列第 2 行」的合法落子、又像命令，语法上没法区分（踩过）。

### 2.2 跑全部单测（不需要板子、不需要 RISC-V 工具链）

```powershell
scripts\gomoku\run_test.ps1
```

5 个测试台 **228 项检查**，外加 RV32 交叉编译检查（7 个 `.c` 文件零警告）。
只要一个 x86 gcc；没装就 `scoop install gcc`。

### 2.3 端到端仿真（在真 CPU + 真 PPU 上跑固件）

```powershell
scripts\gomoku\run_sim.ps1
```

固件启动 → 棋盘铺好 → 长按开局 → 落子 → AI 应手，6 项全过。

> [!] **这个脚本写死用 `-Sim` 口径**（按键阈值 1ms/5ms、AI 用 EASY），不给你选。
> 板上口径喂它只会等到超时：
> * 长按 600ms 在 62MHz 下是 **3700 万拍**
> * AI 的 NORMAL(4 层) 一次搜索约 **2 亿拍** —— 在仿真里要跑 **十几分钟真实时间**
>   （iverilog 约 20~50 万拍/秒）

### 2.4 上板（**没验过，你来验**）

```powershell
scripts\build_bitstream.ps1 gomoku
```

产物：`pds\RV32I_1\generate_bitstream\cpu_top_board.sbit`（会打印 md5）。
**2026-10-04 这一版是 md5 `4d0b9966`、85.0051 MHz 口径，烧完先对 md5。**

> [!] **没有 HDMI 显示器也能验 —— 固件已内置串口棋盘快照。**
> 每次棋子数变化就打一张 15x15 ASCII 棋盘（`X` 黑 / `O` 白 / `.` 空 / `*` 最后一手），
> 外加一行 `cursor=<列字母><行号> you=<人执方> turn=<该谁走>`。
> 所以**显示器只是"锦上添花"，功能验证可以完全靠串口做完**：
> 按键 → 光标移动（看 cursor 那行）→ 长按落子（看棋盘）→ AI 应手（看棋盘 + nodes/depth/t）。
> 唯一**必须**有显示器才能验的是最后一段：**TMDS 编码 / 显示器认不认 480p 时序**。

**烧录是三步，中间那步不能省**：

```
PDS → TOOL → Programmer
  1) Operations → Scan Device
  2) Operations → Assign New Configuration File   ← 选中上面那个 .sbit
  3) Operations → Program...
```

> [!] Fabric Configuration **记住上次分配的文件**，而且是在"分配时"读进内存的。
> 只点 `Program` 会重烧上次那份。**两个位流的文件名和字节数完全相同，肉眼分不出** ——
> 2026-10-01 实踩过一次（想烧视频彩条，结果烧成了 CoreMark）。**烧完先对 md5。**

**板级判据（按顺序）**：

| 看什么 | 期望 | 说明 |
|---|---|---|
| **丝印 D18** 的灯 | 常亮 | = `video_locked`。**不亮就是视频 PLL 没锁，屏幕不会亮，先查这个** |
| 丝印 D19 | 常亮 | = CPU `pll_locked` |
| 串口 | banner + 按键用法 | `scripts\serial_monitor.ps1 -Port COM4 -Seconds 30` |
| HDMI 显示器 | **15×15 棋盘 + 红色光标圈** | 接上 HDMI 线 |

操作：**SW4/5/6/7 = 左/右/上/下**；短按移动光标，**长按 0.6 秒落子**；
标题屏长按任意键开始；**SW3 = 复位**。

## 4. [!] 还没实现的功能（**这一节最重要**）

### 4.1 完全没有的

| 缺什么 | 说明 |
|---|---|
| **HUD / 任何文字** | **屏幕上只有棋盘和光标**。没有"轮到谁"、没有胜负提示、没有难度显示。v1 是刻意不做文字（省 10KB 字库），但**这意味着玩家得自己看棋子颜色判断轮次** |
| **音效** | 没有 |
| **板上悔棋** | CLI 里有（`u`），**固件里没有** |
| **难度在板上的实际手感** | 标题屏能切三档，但 **HARD(6 层) 在板上一手要多久，没测过** |

### 4.2 板上耗时**没标定** —— 这是最大的技术未知

`scripts/gomoku/ai.c` 里有个常数：

```c
#define AI_NODE_BUDGET  40000u   /* 单步搜索的节点数上限 */
```

它的作用是"超预算就退回上一轮完整搜完的结果"（迭代加深保证总有上一轮），
**但它该取多少，在板上没测过**。仿真里量到的是：

| 档 | 每步节点数 | x86 耗时 |
|---|---|---|
| EASY（贪心）| 14 | ~0 |
| NORMAL（4 层）| ≤342 | ~1.6 ms |
| HARD（6 层）| ≤1520 | ~10 ms |

**x86 到 62MHz RV32 的换算系数没测过**。在最坏情况下（自对弈里见过 35,106 节点的局面），
如果系数是 100，单步就是 20 秒 —— **那 HARD 档根本不能用，只能开两档**。

**怎么标定**（建议第一件事就做）：写一个最小的测试固件，把几个固定局面喂给 AI，
用 `mtime`（`hw_port.h` 的 `hw_mtime()`）量真实周期数，把系数测出来。

### 4.3 继承自 CPU 的已知限制

* **不支持未对齐访存**（`ma_data` FAIL 属架构取舍，RISC-V 规范允许）
* **只支持 M 模式**（`mstatus.MPP` 硬连线）
* **外部中断 MEIP**：通路具备但**没有测试**，不得当成已验证能力

### 4.4 应用场景层面还缺的

* **演示视频 / 照片**：`doc/board/` 里只有串口文本和 ILA 波形，**没有录像/照片**
* **游戏本体还很朴素**：只有单局对弈，没有多关卡、没有得分、没有开场画面
  （`doc/reports/2026-10-01_gomoku_worklist.md` §5 v2 里设想的内容都还没做）

## 6. 硬件事实（写代码前必须知道）

### 6.1 按键方案 —— 为什么是"短按移动 / 长按落子"

板上**只有 4 个用户按键**，却要干 5 件事（上下左右 + 落子）。这是刻意的取舍：

```
按下 ─┬─ 松手（<600ms） -> 一次【短按】= 移动光标一格
      └─ 撑到 600ms    -> 一次【长按】= 在光标处落子
```

**[!] 两个事件都不在"按下沿"触发。** 若改成"按下沿就移动、长按再落子"，
按住方向键落子时光标会**先跑一格** —— 想在 A 点落子却落到 A 的下一格。
现在这样，"按住不放落子"的净效果就是**光标一动不动地落子**。
代价：移动要等松手（约 100ms），且**没有连移**。

### 6.2 板上有 6 个开关，但只有 4 个能用

| 丝印 | 手册 | 引脚 | 用途 |
|---|---|---|---|
| **SW2** | 复位按键（带 LED **D22**）| **未知** | **[X] 用不了** —— 见下 |
| SW3 | KEY0 | C22 | 被 `resetn` 占用 |
| SW4~SW7 | KEY1~KEY4 | C23/B22/A22/B20 | 4 个用户键 = key[0..3] |

> [!] **SW2 为什么用不了**：按它时 **INIT 灯有反应** —— `INIT` 是 FPGA 的**配置引脚状态灯**，
> 说明 SW2 接的是配置逻辑（`INIT_B`/`PROGRAMN`），**专用脚不能当普通 IO**。
> 这也解释了手册里为什么找不到它（在配置章节，不在用户按键章节）。
> **想要第 5 个键，只有 40Pin 扩展口外接按钮这条路。**

### 6.3 其它

* 上板顶层是 **`cpu_top_board`**（不是 `cpu_top`）—— 后者引出的 `pc[31:0]`/`done`
  会被 PDS 自动布到 BANKR5 的真实引脚（板上接的是 SFP/HSST）
* **Jtag 和 USB UART 是两块独立接口，要插两根 USB 线** —— 只插 Jtag，串口永远没输出
* 板上时钟 **85.0051 MHz**（板载 27MHz 经 PLL，`STATIC_RATIO0=13.5`），`EE_TICKS_PER_SEC` 等 4 处常量要同步

## 7. 修改时要守的纪律

1. **改完 C 代码，跑 `scripts\gomoku\run_test.ps1`**（228 项）—— 它同时会检查
   RV32 交叉编译零警告（**仿真能过不代表板上能过**）
2. **改了影响渲染/对局的逻辑，跑 `scripts\gomoku\run_sim.ps1`**
3. **别碰 `rtl/`** —— 五子棋是纯固件，一行 RTL 都不用改。改了 RTL 要走全量回归
   （riscv-tests 49/1/0 + CoreMark 区间 363,515 拍）
4. **上板前用 `build_bitstream.ps1`，别手工分步** —— 它带 sha256 校验，
   能挡住"工程里留着旧 mem.hex"这个零报错的坑
5. **`expectLines` 会随固件变**：改了代码导致 `mem.hex` 字数变了，
   脚本会拦下来并提示你更新它 —— **那是守卫在工作，不是 bug**
