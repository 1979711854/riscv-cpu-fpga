## 3. ★ 本次踩的坑（都已写进 `CLAUDE.md` 关键约定 13-15 条）

都是**静默出错、极难排查**那一类，值得先看一遍：

1. **测试台悬空的输入端口是 Z，不是 0。** `tb_riscv.v` 漏接 `mem_bus.irq_timer`
   → `mie.MTIE & Z` 是不定态 → 中断行为随机。**症状：同一份 RTL、同一份 hex，
   调试台跑出"正常停在 PASS 自旋"，tb_riscv 跑出 pc=0x30a70**。
   两个测试台结果不一致时，先怀疑接线不一致。
2. **C 预处理器会把 `.text.init` 拆成 `.` `text` `.` `init`。**
   `#define init nop` 把段名静默改成 `.text.nop`，链接脚本匹配不到、内存布局错位
   （`_start` 从 0x0 跑到 0x1000）。上游用**汇编宏**正是为了避开这个。
3. **"全零字按气泡处理"是承重的。** 取指是同步读、1 拍延迟，复位后第一拍
   IF/ID 锁存到的是存储器复位值 `0x00000000`；`control.v` 的 `default` 必须对它
   例外（否则上电第一拍就 trap），`core.v` 的 `if_id_valid` 也用它判"是不是真指令"。
4. **trap 必须同时清 EX/MEM，只清 ID/EX 不够。** `EX/MEM <= ID/EX` 是**同一个沿**
   发生的，清 ID/EX 只保证下一拍是气泡，这一拍 EX/MEM 照样把肇事指令收下 ——
   实测现象是"未对齐 sw 既正确陷入了 mcause=6，内存却也被改了"。
5. **CSR 写必须从 EX 级提交**（不是 WB）。riscv-tests 里 `csrw mepc, t0` 与 `mret`
   只隔 1 条指令，从 WB 提交会让 `mret` 读到复位值 0 → 跳回 `_start` → 50 个 TIMEOUT。
6. **`csr_wr_illegal` 只看地址，必须与"这条指令真的在写吗"相与。**
   `csrr a0, mhartid` 是 RS 且 rs1=x0、根本不写，却被判成非法 → init 每轮 trap。

### 不建议做

* **2 路组相联 I/D Cache**：存储器是行为级单周期 BRAM，访存恒 1 拍、无缺失惩罚、
  无结构冲突 —— 加 Cache 只会引入缺失惩罚，**是负收益**（详见 `doc/resource_efficiency.md`）
* **边缘 AI**：32KB BRAM 是硬墙（无片外存储），当前硬件条件下不可行
