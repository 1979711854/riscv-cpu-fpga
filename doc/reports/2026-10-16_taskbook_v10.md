## 1. 本轮（v9 → v10）已完成

### 1.1 A1 实现完成、**判定不采纳**（效率 +0.181%，但代价是净表 +122 LUT 与余量作废）

* 实现：`rtl/core/core.v` 6 处（配对白名单加 `STORE` + 新增 `p_b_rd_ok`；`p_mem_a && p_mem_b`；
  写口三腿 + `ex_mem_b_wdata`；`ld_bad_st` 并 lane B 支；未对齐 store 进异常）+ `cpu_top.v` 透传。
* 判据全绿：关档 `217,088` + 四 CRC 逐位不变、`LANEB_ST=1` 时 **216,695（−393 拍 = −0.181%）**、
  riscv-tests 49/1/0、own_tests **7/0**（新增 `sim/tests/tb_laneb_st.S` 八个 store 定向用例）、
  **反例对照**（摘掉 `ld_bad_st` 的 lane B 项 ⇒ 用例 1 FAIL）证明用例有牙齿。
* **不采纳的理由（量化）**：LUT `7,767→7,889`（**关档就已 +122**，FF 3,691 不变）；
  净表一变，钉住的 `gplace_seed 5` 余量就作废（**+0.277 → −0.156 ns / 85 MHz 下 5 个失败端点**），
  而 rev1027 原样 RTL 重跑**逐位复现 +0.277 / 端点 19,114**（⇒ 流程确定，不是抖动）。
  不重扫 seed 就要降频 85→83 MHz（**score ∝ 频率 ⇒ 直接亏 2.4%**），重扫 40 跑只换 +0.18% ⇒ 不值。
* ⇒ 处置：`LANEB_ST` **默认 0**（`core.v` / `cpu_top.v` 注释写明理由与启用前置条件），
  与 I/D Cache、`A_EXT` 同款"实现 + 量化评估后判定不启用"。

### 1.2 A2 / A3 判定：**已被历史实测否证，不用再做**

* **A2 配对率扩展**：`2026-10-15_pair_rate_analysis.md` 证明 `pair_analyze.py` 模型与实现脱节、
  "分支配对"**早已实现**；周期侧唯一剩的门是"给 lane B 访存能力"（上界 +7.46%），
  而 store 只是 **+0.43% 模型值 / +0.181% 实测** ⇒ **这条线走完**。
* **A2 实测补强（本轮 `+PROF`）**：交付档 `region cycles 217,088` / `region commit 195,094（89.9%）`
  / `region noretire 21,994（10.1%）` ⇒ **配对 92,962 对（32.3%）**、流水线已接近"提交受限"；
  剩余结构性余量 = `195,094 − 144,028 = 51,066 拍`，主因是**"lane B 不能是分支/跳转/CSR/AMO"**
  这条结构限制 ⇒ 动它 = 换结构级别，**不做**。
* **A3 BTB 扩容**：BHT 256→1024 实测 **+0.10% 已回退**（`da45e41`）；
  `+JALRTRACE` 实测 `jalr` 1,374 条 **100% 是函数返回**、直接映射 BTB 在 **16~16384 项**下
  捕获率**恒 6.40%**（不是冲突）⇒ **扩表无效**，正解 RAS（8 项 99.93%）**已进交付档**。

### 1.3 A4 判定：**不做**（0 成本推导即否，未动一行 RTL）

* 落点已探明：那条关键路径的 DRAM 是 **`u_pat` pattern 显存**（`rtl/video/video_core.v:89-99`，
  `vram_b32.v:50-51` 同步读）；视频窗口读的**唯一消费者 = 地址落在视频窗口的 CPU load**，
  固件只读 `VIDEO_STATUS`（寄存器窗口，`scripts/gomoku/video_port.c:62`），CoreMark/固件**都不读 pattern 窗口**；
  `mem_ready` 唯一产生点 `mem_bus.v:373-374`（视频区现恒 1）。
* **两条硬结论**：① **"只多压一拍 `mem_ready`" = 零收益**（那条链是**同沿内**组合链，
  压拍只改流水线相位，网表里那一级逻辑还在；被 enable 挡住的 D 端路径 STA 照样分析）；
  ② 要真去掉必须**把视频读数据打拍**，而这会撞 core 的读数据契约
  （`load_src = snap_en ? wb_rdata_snap : mem_rdata`，快照在**停顿第一沿**抓 `mem_rdata`，
  见 `core.v:1764-1797`）⇒ 要加"迟到读数据"端口 + 在 `load_src` 前**再加一级 mux**
  （**正好加在要缩短的那条链上**，每级 ≈ 0.2~0.3 ns），而**尾段（lane B 解包→前递→ALU lt→
  分支解析→重定向→`imem_addr2`→ADB 高扇出 1.201 ns）仍需 ≈ 9.4~11.1 ns 去挤 11.76 ns 周期**
  ⇒ 赢面不明、代价确定 ⇒ **不做**。
* 三处剩余瓶颈的处置：跨模块线 1.760 ns（切了不解决命门）/ ADB 高扇出 1.201 ns
  （只能靠取指地址再打一拍 = 直接亏分）/ 时钟树 1.615 ns（物理项，不在 RTL）
  ⇒ **Fmax 在 RTL 侧到顶**（`+0.277` 距 `+0.3` 判据差 0.023 ns）。

### 1.4 论文：**第 3 / 5 / 6 章已写完**（`doc/paper/正文_v0_20261016.md`）

* 第 3 章 微架构（8 节）：双发射判据 → lane B 访存两级（含 A1 的"实施完成 ≠ 应当采纳"闭环）→

* 第 5 章 验证（4 层体系 / 5 条回归纪律 / 6 个案例研究 / 板级证据链 / 未覆盖清单）。

## 3. 硬约束与坑（每条都踩过）

1. **`gplace_seed` 只对某一版净表成立**：任何 RTL 改动（**哪怕仿真逐位等价、哪怕 FF 数完全相同**）
   都要假设余量作废；出位流前先**单跑一遍**核对 CPU 域（本轮实测：+122 逻辑 LUT ⇒ +0.277 → −0.156 ns）。
2. **"关档 ⇒ 逐位不变"只在仿真层成立**，综合层不成立（见第 1 条）。
3. **PDS 每次跑完都会重写 `.pds`**：改选项要在流程空闲时做、跑完复核；
   `(_option gplace_seed (_integer 5))` 必须在。跑完 `git checkout -- pds/RV32I_1/RV32I_1.pds`
   可清掉纯时间戳噪音。
4. **钉单 seed 时 P&R 阶段不出 `.rtr`** ⇒ 用时序从 `report_timing/cpu_top_board.rtr` 兜底收
   （`scripts\capture_seed_timing.ps1 -Parse <文件>`）；**别拿"全设计最差"排序挑 seed**
   （跨域 `CPU→pix_clk` 是既有伪影，4 批默认挑种里 2 批挑出时序不过的布局）。
5. **`.sbit` 的 md5 不是布局指纹**（同布局两次构建 md5 不同）⇒ 引用位流给
   **"md5 + 来源报告 + 日志时间"三件套**。
6. **改 `scripts\*.ps1` 必须保持 UTF-8 BOM**（PS 5.1 否则按 GBK 读中文注释）。
7. **长仿真按实测估时**：本机 168 ms 仿真时间 ≈ 24 min 墙钟（iverilog 慢；
   五子棋端到端一次 ~24 min）；CoreMark ITER=1 约 2~3 min。
8. **提交纪律**：上板前必须重跑 `scripts\build_bitstream.ps1`（唯一入口，含 `mem.hex` sha256/行数守卫）；
   **绝不烧来路不明的 `.sbit`**。commit 信息写清"改了什么 + 判据"，push 到 `origin/dualissue`。
9. **`tb_video_core.v` 的 `mem_rd` 硬编码 1 拍读**（`sim/tb_video_core.v:168-178`）——
   若哪天真去动视频读的等待拍，**必须同步改它**，否则视频单测会误报。
10. **RTL 里的契约注释是承重墙**：`mem_bus.v` 头部（读 1 拍 / 写零寄存器 / 空闲期 ready 必须为 1）、
    `core.v` 的 WB 快照契约、`control.v` 的译码白名单——改行为**必须同步改注释**，
    否则下一个人会按注释把坑挖回来。
11. **A1 的代码在树里但默认关**：`LANEB_ST=0`；任何"回退/翻开关"都要重跑
    `sim/tests/tb_laneb_st.S` + 全量回归（关档 217,088、开档 216,695）。
