## 3. 各任务细节

### 3.1 [必修] `video_wait_vblank()` 会永久挂死

**现象（2026-10-07 实测）**：按复位后，**固件卡死** —— 串口只打出 banner，
之后一句都不再有；按键也全死。

**根因**：`scripts/gomoku/video_port.c:45`

```c
/* [重点] 这里忙等，而且没有超时保护 —— 如果视频 PLL 没锁（pix_clk 不走），
 *         这个位永远不变，程序会卡死在这里、串口也不打印，看起来像"死机"。*/
while ((REG32(VIDEO_STATUS) & 1u) == 0u) ;
```

**日志证据**：banner 每 7 行重复一次（一个 banner 正好 7 行），
且**只有第一次启动打出 `level=`** —— 后面每次都走不到主循环第一拍。
主循环的第一句就是 `video_wait_vblank()`。

**为什么复位后会没有 vblank**：`rtl/video/video_top.v:91` 的
`wire vid_resetn = resetn & locked;` —— **视频域跟着按钮复位一起被复位**，
视频没恢复就永远没有 vblank。

**改法（两条都做）**：

1. **`video_wait_vblank()` 加超时**：用 `hw_mtime()` 判，超时（比如 50ms）就返回。
   **判据：视频失锁时，串口仍能打印、按键仍能响应 —— 不再"死机"。**
2. **把 `vid_resetn` 与按钮复位解耦**：改成只由视频 PLL 锁定门控
   （`wire vid_resetn = locked;`），按钮复位不再打断视频。
   这样按复位只重启 CPU，画面不中断。

> [!] 一个固件因为外设没就绪就永久挂死，本身就是缺陷。**注释承认了问题却没修。**

### 3.2 [必修] 双重 LEVEL 显示

**现象**：进对局后屏幕上**同时出现两行 `LEVEL:`**。

**根因**：`scripts/gomoku/main.c` 的 `draw_hud()`

```c
if (g_game.phase == GAME_TITLE) {
    ...
    render_text_center(3, line);   /* "LEVEL: NORMAL" 画在【行 3】 */
    ...
    return;
}
/* 对局屏 */
render_text(2, 1, line);           /* "LEVEL: NORMAL" 又画在【行 2】 */
```

**进对局后，标题屏留在行 3 的那行没被清掉。**
（注意：2026-10-07 修的是"**同一行内**的残字"，这个是"**别的行**没清" —— 同类问题的另一种形态。）

**改法**：`draw_hud()` 在非标题屏时，把标题屏专用的行（3 / 27 / 28）也清成空格字模。
**改动会随任务 C 的菜单重排一起做掉，别分两次。**

**回归锁**：`test_render.c` 里补一条 —— 从标题屏进对局后，标题专用行必须是空格字模。

### 3.3 菜单系统（P0）

**交互（用户明确描述过）**：**上下键选择 + 长按确认**，多级菜单。

```
标题屏 → 模式（人机对弈 / AI 对弈）
   ├─ 人机对弈 → 难度（EASY/NORMAL/HARD）→ 执子（人执黑先 / 人执白后）
   └─ AI 对弈  → 黑方难度 → 白方难度 → 每手间隔（快 0.5s / 中 1.0s / 慢 2.0s）
```

**数据结构**：现在 `game_t` 只有一个 `level`，要拆开：

| 字段 | 用途 |
|---|---|
| `mode` | 人机 / AI 对弈 |
| `level_black` / `level_white` | **双方各自难度**（人机对弈时只用人那方的对手）|
| `human` | 人执黑还是白（**已存在**，现在硬编码成黑）|
| `step_ms` | AI 每手间隔 |
| `menu_stage` | 当前菜单层 + 高亮项 |

**`game_ai_turn()` 现在用 `gm->level` —— 改成按执子方查 `level_black`/`level_white`。**
现有的 `demo` 字段并进"AI 对弈"（现在的演示模式是 NORMAL vs NORMAL 固定）。

**验收**：`test_game.c` 的标题屏用例要跟着更新（现在测的是"左右键切难度"），
并给菜单状态机补用例（进/出各层、上下键循环、长按确认、返回）。

### 3.5 AI 思考时画面卡顿（P0）—— **实测最长 1.4 秒**

**现象**：用户原话 —— **"AI 下棋的瞬间，红色光标会卡顿一下"**。

**实测**：AI 一手 **171 ms ~ 1,433 ms**（NORMAL，31 手一整局）。这一整段时间里
**主循环停住 → 光标闪烁也停了**。

**根因**：AI 同步阻塞，`draw_frame()` 要等 AI 跑完才执行。

**改法（G1 + G2，已在 v4 任务书论证过）**：

- **G1**：人落子后**立刻刷一次屏**，再进 AI —— 你马上看见自己刚下的子
- **G2**：AI **按迭代加深的层数分批**，每层搜完回主循环刷一次屏 ——
  画面跳 2~3 次，且 **HUD 那行 `AI: NODES` 的数字在涨**（演示上是加分项）

**不做 G3**（RT-Thread 或纯协程重写）—— 内存装不下 / 递归改迭代风险太高，见 v4 §3.5。

## 5. 纪律与坑（都是踩过的）

1. **两条并列回归基线**：双发射（默认）49/1/0 + 313,886 拍/迭代；
   单发射（`-Single`）49/1/0 + 363,515。**改 RTL 两条都跑。**
2. **[!] 变短/换行的字符串要整行重写** —— `render_text` 已改成整行写（先铺满空格再覆盖）。
   **菜单高亮移动时同理：上一处的高亮必须被擦掉。**
3. **[!] 板子上别按 SW2/D22** —— 那是 FPGA 配置键，按了设计被卸载（两灯全灭/屏幕黑/
   串口静默），必须重新下载位流。**真复位是 SW3。判据：按完两个 PLL 灯还亮不亮。**
4. **中文 Windows 的编码陷阱**：无 BOM 的 `.ps1` 被按 GBK 读 → 假语法错；
   原生命令输出被按 GBK 解码 → 中文文件名变乱码。样板见 `scripts/pack_for_teammate.ps1`。
5. **别碰 `rtl/`** —— 五子棋是纯固件。任务 A 的第 2 条要改 `video_top.v`，那要走 RTL 全量回归。
6. **串口可观测性**：任何玩家可感知的动作都要有输出，且**要先判断再打**
   （踩过：把 `AI thinking...` 挂在"长按"上，落子失败时打出却没有下文）。
