## 1. 一句话

## 3. [OK] 砍 RV32A（提交 `b05bb82` / `e6ae9bf`）—— 位流 `55fae69e`

用户批准（"RV32A 可以砍"）。依据：两个交付固件**都不含原子指令**
（CoreMark `-march=rv32im_zicsr` 编译器发不出；RT-Thread 档 ELF 实测 0 条 ——
反汇编 0 命中、原始机器码扫 opcode `0101111` 只命中 2 个 ASCII 字符串）
⇒ **零性能代价，纯省面积**。

| | 之前 `f64b977` | 现在 `55fae69e` |
|---|---|---|
| LUT | 8,104 | **7,663**（−441 / −5.44%）|
| FF | 3,899 | **3,675**（−224）|
| DRM | 101.5 | 101.5 |
| CPU 域 slack | +0.034 ns | **+0.330 ns**；可达 **87.4585 MHz** |

**回归全部逐位不变**：CoreMark 五配置（229,597 / 249,982 / 287,056 / 300,392 / 233,013）、
四 CRC、riscv-tests 49/1/0、own_tests 5/0、RT-Thread 仿真两配置 PASS、`tb_amo_int` T0 PASS。

**实现要点**（都在 `rtl/core/core.v`）：
* `parameter A_EXT = 0`（默认关）；`amo_unit` 用 **`generate` 包住不例化**
  —— 只把 `start` 接 0 **不够**（单元内部锁存/状态机寄存器不依赖 start 的常量性，
  综合器不会证明它们恒为常量，面积省不下来）。
* `A_EXT=0` 时 AMO 的 opcode **补一条 `illegal`**（RISC-V 规定未实现扩展 ⇒ mcause=2）。
  **已单独验证**：拿 `amoadd.w` 的程序跑，`RAM[0x2000]` 不被改写、`ST_LATCH=0`、
  pc 钉在 `0x00000004` 反复走 trap 向量 ⇒ 判非法陷入，**不是静默执行、不写坏内存**。
* `DESIGN_REV` → `0x2026_1023`（约定 42）。
* **验证口径保住**（"RV32A 实现并验证过"的证据链不断）：`tb_amo_int` 写死 `A_EXT=1`；
  `run_own_tests.ps1` 传 `-DAEXT`（套件含 `tb_amo_cpu`，不传会 testnum 668 FAIL，
  **那是预期行为**）；`rtthread\run_sim.ps1 -Atomic` 传 `-DAEXT`（硬件原子固件）；
  `run_riscv_tests.ps1` **不传**（回归集无 rv32ua，`A_EXT=0` 才是板上口径）。

三条会咬人的（任务书 §7 自己列的，我复核后确认都成立）：
* **R1** 四个 `fwd_*_exb` 没排除 `wb_sel==01` ⇒ lane B 的 load 会把**地址**当前递值
* **R2** `ld_bad_base` 只查 `id_ex`/`id_ex_b`/`ex_mem`，**漏了 `ex_mem_b`**
* **R4** 四处级间寄存器的**清/保持/锁存**每个分支都要加新字段，漏一处就是静默错
* 另：**不加 `!ex_flush` 给 lane B 的 read**，靠 `ex_mem_b_valid` 门控 `b_mem_sel`
  —— 这一点**必须写进注释**（否则后人会当冗余清掉，任务书 R6）

不影响主分 ⇒ 这个闸门已从"作废闸门"降级为"看掉多少、值不值"。
