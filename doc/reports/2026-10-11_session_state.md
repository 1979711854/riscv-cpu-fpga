## 1b. 任务 C 的时序评估（2026-10-11 完成）

报告：`doc/reports/2026-10-11_taskC_agu_probe.md`；约定：`CLAUDE.md` **44**

| 配置 | CPU 域 slack |
|---|---|
| 基线 | **+0.578 ns** / 89.398 MHz |
| 假 AGU 开着 | **+0.148 ns** / 86.088 MHz |

**Δ = −0.430 ns**（余量从 4.9% → **1.3%**，仍为正）。
⇒ 与 A.1 假 tag 探针的 0.452 ns 同量级 ⇒ **"插一级 32 位逻辑"的标准代价 ≈ 0.43 ns**。

> [!] **探针只量到 AGU 那一小块 —— 任务 C 真正的风险在"改协议"**：
> 地址提前到 ID 会引入新的**地址-use RAW**（可能新增停顿把收益吃回去），
> 且 `mem_addr/mem_we/mem_re` 要从 EX/MEM 改成 ID/EX 驱动，
> 而 **AMO 的 4 拍状态机、`mem_ready` 冻结、trap 的 EX/MEM 清除** 全建立在这之上。
> **推进顺序（报告 §5）**：先只把 **load 的地址**提前（store/AMO 不动），
> 用最小改动量把收益量出来，再决定要不要搬其余部分。

## 1d. Cache 重估（2026-10-11 晚，任务 C 之后）

同一台机器、同一套 `pds_shell -run pnr`，**只换 Cache 开关**：

| 配置 | C 之前 | **C 之后** |
|---|---|---|
| 都不开 | +0.544 | +0.045 |
| 只开 D-Cache | — | **+0.151** ✓ |
| I+D 全开 | −1.586 | **−0.844** ✗ |

* **D-Cache 的时序代价消失**（快通路 load 不再占 B 口 ⇒ tag/way 移出访存关键路径）—— §7.4 的假说成立。
* **I-Cache 仍塞不进**（挂在取指链上，任务 C 没动它）。
* **收益仍是 0**：开 D-Cache 只让每迭代 241,633 → **241,998（+0.15%）**，且它只服务
  没走快通路的 9,943 次访存（命中率 93.5%，**不是**原来那个 98.47% 的口径）。
* ⇒ **默认仍关**，理由改成"**塞得进 D、塞不进 I，而两者都不涨分**"。
  详见 `2026-10-11_cache_impl.md` §7.5 与 `CLAUDE.md` 约定 43 末尾。

## 1c. 任务 C 的实测（2026-10-11 完成第一步）

报告：`doc/reports/2026-10-11_taskC_early_ld.md`；约定：`CLAUDE.md` **45**

| 版本 | 拍/迭代 | 快通路 load | 剩余停顿 |
|---|---|---|---|
| 基线 `EARLY_LD=0` | **262,018** | — | 27,181 |
| `EARLY_LD=1` | **241,633**（−7.79%）| 85.0% | 6,796 |

**区间上限 24,568 拍（9.38%）拿到 20,385 拍（7.78%），兑现率 83%。**
剩下的：**基址在 EX 4,744 拍（1.81%）** / 紧前是 store 1,869 拍（0.71%）。
**ITER 用 4,116**（`build_bitstream.ps1` 默认值已改）。

> [!] **时序是唯一的保留项**：同一份 RTL 连跑三次 P&R，CPU 域 slack 分别是
> **+0.208 / +0.035 / −0.156 ns** —— **散布就有 0.3 ns**（约定 25 的老问题）。
> 基线（`EARLY_LD=0`）历史四份报告是 +0.544 ~ +0.879，**明显更宽**。
> 所以：**上板前必须先看当次 P&R 报告的 CPU 域 slack**；为负就重跑（或 `EARLY_LD=0` 回退）。
> 快通路本身不占关键路径（第一版连跑时最差路径仍是乘法器），
> 是"多一份 BRAM + 两级前递 mux"带来的**布局扰动**在主导。

## 2. [重点] 钉死的结论（别再重新论证）

| 结论 | 依据 |
|---|---|
| **85 MHz 下塞不进任何形态的 Cache** | 四个配置实测：不开 +0.544 / 只 I −1.128 / I+D(16K) −1.586 / I+D(4K) −1.092 |
| **"缩小 Cache"只解决三分之一** | 面积砍 75% 只换回 0.5 ns，剩下是逻辑深度 |
| **降频演示这条路是坏的** | 请求 71.72 MHz → 实际 61.92、slack −2.208，**比请求 85 还差** |
| **Cache 对分数贡献是 0** | 命中 1 拍 = 零收益（后端单周期 BRAM）；参考设计缺失率 0.000% |
| **生产位流逐位不变** | 回归复测 Total ticks = 262,018、四个 CRC 全对 |
