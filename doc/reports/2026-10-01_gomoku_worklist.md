## 0. 一页速览

**一句话结论：五子棋是【纯固件工程】，CPU / 显示 / 输入 / 定时器全现成，一行 RTL 都不用改。**

| 问题 | 答案 |
|---|---|
| 显示怎么做 | 已有 **HDMI 480p60 tile PPU**（`rtl/video/`），显存映射在 CPU 地址空间，软件直接写字节就出图。**不是** SPI TFT（那是旧方案，已作废） |
| 输入怎么做 | 已有 **8 个按键**（低有效，需软件去抖），够"上下左右 + 落子 + 重开" |
| 要不要改 RTL | **不要**。全部是 C 固件，零时序/回归风险 |
| 内存够不够 | CPU 32KB 只管代码+数据，**显存 73KB 是独立的 BRAM，不占 CPU 内存**。裸机五子棋约 10~16KB，绰绰有余 |
| 做不做 AI | 做。分 PvP（人机 vs 人人）和 PvE（打 AI，启发式评分或浅层 minimax） |
| 用不用 RT-Thread | **第一版用裸机**（跟 `video.c`/`demo.c` 同一套，风险最低）。RT-Thread 是加分项，见 §4.3 |

## 1. 硬件现状：游戏能用的全部现成外设

> 精确地址以 `rtl/bus/addr_map.vh`（RTL 侧）与 `scripts/demo/addr_map.h`（软件侧）为准，两处必须一致。下表是照抄的。

### 1.1 显示 —— HDMI tile PPU（480p60）

- 屏幕 **640×480**，像素时钟 25.5MHz，HDMI/TMDS 输出，**已实现**（`rtl/video/video_core.v` + `ppu.v` + `sync_vg.v`）。
- **无精灵、无线性 framebuffer**：只有一层"图块背景"，三块显存：

| 显存 | 地址 | 大小 | 内容 |
|---|---|---|---|
| nametable 图块表 | `0x8001_0000` | 8KB | 32 行 × 256 列的 tile 号（1 字节/tile），**字节地址** `r*256+c` |
| pattern 图块像素 | `0x8002_0000` | 64KB | **256 个图块**，每块 16×16 像素，1 字节 = 调色板索引，字节地址 `T*256+py*16+px` |
| palette 调色板 | `0x8003_0000` | 1KB | 256 项 × 24bit RGB，字地址 `i*4`，`0xRRGGBB` |

- 控制寄存器（**只接受整字写 `sw`**）：
  - `0x8003_0400` scroll_x[11:0]，`0x8003_0404` scroll_y[11:0]（世界坐标滚动，12 位环绕）
  - `0x8003_0408` 状态，**bit0 = vblank**（帧消隐期，宽 62.7us≈CPU 3100 拍）
- **世界坐标**：`world_x = x + scroll_x`，`world_y = y + scroll_y`。世界 4096×512 像素 = 256×32 块；屏上可见 40×30 块。

> **关键理解**：PPU 每像素依次读 nametable → pattern → palette 三级（6 拍延迟，内部已对齐）。
> 软件**只做两件事**就能出图：① 把要用的颜色写进 palette；② 把 16×16 图块像素写进 pattern；③ 把图块号写进 nametable。剩下滚动/扫描全由 PPU 干。

### 1.2 输入 —— 8 个按键

- 读 `0x8000_0000`（GPIO），返回 `{key[7:0], led[7:0]}`，**key 低有效**（按下=0）。
- 硬件**只做 2 级同步，不做消抖**（`rtl/periph/gpio.v` 注释明说：消抖放软件）。demo.c 已有 10ms 软件去抖样板，直接抄。

### 1.3 定时器 / 中断

- `mtime` = `0x8000_0010`（32 位自由跑周期计数，= 板上 49.8927MHz）。
- `mtimecmp` = `0x8000_0014`，`mtime >= mtimecmp` 拉 MTIP（bit7），写新值自动落。可用来做光标闪烁 / AI 思考限时。

### 1.4 UART（调试终端）

- 发 `0x8000_0008` 写一个字符；收 `0x8000_000C`（bit31=valid，读会弹出）。**开发期调试、以及"棋盘坐标用串口打印"都靠它。**

### 1.5 内存账（最关键的约束）

| 资源 | 大小 | 归属 |
|---|---|---|
| **CPU 程序+数据** | **32KB**（实际可用到 `0x7FEF`，栈顶 ≤ `0x7FF0`） | 五子棋固件 |
| nametable | 8KB | 视频（独立，不占 CPU 内存） |
| pattern | 64KB | 视频（独立） |
| palette | 1KB | 视频（独立） |

- CoreMark 代码+数据共 16.4KB；裸机五子棋（含简单 AI）预计 **10~16KB**，装得下。
- **不要让队友误以为"显存 73KB 会挤爆 CPU 的 32KB"** —— 两者是分开的 BRAM。

## 2. 关键约束（开工前先背，都是踩点）

1. **没有精灵：棋子必须"烤"进图块。** 一个棋盘格显示什么，取决于"该格的网格线形状 × 有没有棋子 × 有没有光标"。所以 pattern 里要预生成一批图块（见 §5 A2），改一格 = 改 nametable 里那 1 个字节。**图块预算 256 块**，§5 算过约 110 块，够。
2. **改显存要在 vblank 里做**，否则可能撕一条（上半屏旧格、下半屏新格）。改前 `while (!(VIDEO_STATUS & 1)) ;` 等 vblank。棋子一格一格落，撕裂只影响一格、且只有 1 帧，**可接受**，但光标移动频繁，最好也顺带做。
3. **按键要软件去抖**（10ms），且是**低有效**（按下读到 0）。8 键分配：↑ ↓ ← → / 落子 / 重开（还有 2 个富余）。
4. **不改任何 RTL。** 改了就要跑全量回归（`49/1/0` + CoreMark `354,119` 拍），游戏这条线不该碰。游戏是纯 `mem.hex` 固件替换。
5. **`mem.hex` 过期坑**：上板前必须 `sync_firmware.ps1`，否则会烧旧程序、PDS 零报错（`CLAUDE.md` 关键约定）。
6. **编译要用 `-march=rv32im`**（不带 `_zicsr` 也行，游戏若不碰 CSR）；但**若上 RT-Thread 则必须 `-march=rv32im_zicsr`**（见 rtthread README 坑 1）。

## 3. 总体方案（先定这个再分工）

### 3.1 棋盘怎么摆（给 A 轨道的默认方案）

- **默认：1 格 = 1 图块（16×16）**，棋盘 15×15 格 = **240×240 像素**，摆在屏幕中央，四周留给 HUD（当前轮到谁 / 分数 / 标题）。
  - 屏 40×30 块，棋盘 15×15 块，居中：列起点 `(40-15)/2 = 12`，行起点 `(30-15)/2 = 7`（取整）。
  - 棋盘在 nametable 里的行列 = 世界坐标（scroll 保持 0 即可，本游戏不需要滚动）。
- **可选升级：1 格 = 2×2 图块（32×32）**，棋子更大更好看，但棋盘 480×480 撑满整屏、几乎没 HUD 空间。**留给美术队友定**，两套图块表接口一致（都只是"给一个格写像素"）。

### 3.2 数据结构（给 C 轨道）

- 棋盘 `uint8_t board[15][15]`：0 空 / 1 黑 / 2 白。225 字节，或两个 `uint32_t` 位板（快且省）。
- 落子后**增量判胜**：只从刚落的那格沿 4 个方向（横/竖/两斜）各数连子，O(1) 完成，别每次全盘扫。
- 状态机：`标题 → 对局(黑/白轮流) → 胜/平 → 重开`。

### 3.3 交互（给 B 轨道）

- 光标二维移动 + 闪烁（闪烁靠 `mtime` 定时，别用忙等卡死输入）。
- 落子 = 把光标处格写黑/白，交给 C 判胜，然后交给 A 渲染 + 换手。

### 3.4 是否用 RT-Thread

- **第一版：裸机**（`video.c`/`demo.c` 同款），主循环 = 读键 → 更新状态 → 渲染。**推荐**。
- **加分项：RT-Thread**（已通仿真、未上板）。把"输入线程 / 游戏逻辑线程 / AI 线程 / 渲染线程"拆开跑，能展示调度。**但代价是 21.5KB 基线内存 + 上板流程未验证**，作为第二阶段再上，别第一版就赌它。

## 8. 队友最容易搞错的 5 件事（写在最显眼处）

1. **"显存 73KB 会不会挤爆 32KB？"** —— 不会，显存是独立 BRAM，CPU 32KB 只放代码+数据。
2. **"棋子要不要做成精灵？"** —— 没有精灵，棋子是烤进 pattern 的图块，改一格 = 改 nametable 1 字节。
3. **"按键为什么有时候连跳？"** —— 硬件不消抖，软件必须 10ms 去抖；且 key 是**低有效**。
4. **"屏上怎么一格子花了？"** —— 改显存没等 vblank；棋子落子可接受，光标移动最好等。
5. **"烧了怎么还是旧程序？"** —— `mem.hex` 过期，上板前必须 `sync_firmware.ps1`。
