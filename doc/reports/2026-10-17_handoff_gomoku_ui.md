## 2. 屏幕与图块预算（先看这张，后面所有设计都受它约束）

| 项 | 值 |
|---|---|
| 屏幕 | 40 列 × 30 行 tile × 16px = **640×480** |
| 图块显存 | **256 块**（每块 16×16 = 256 字节） |
| 当前占用 | 棋盘 `0..35`（36）+ 字库 `36..130`（95）+ 装饰 `131..153`（23）= **154** |
| 空闲 | **102 块** |

### 2.1 新布局

```
列 0                                29 30        39
行 0 ┌──────────────────────────────┬────────────┐
     │                              │            │
     │   15×15 棋盘                 │  HUD       │
     │   每格 2×2 tile = 32×32px    │  10 列     │
     │   30×30 tile = 480×480px     │  160px     │
     │                              │            │
行29 └──────────────────────────────┴────────────┘
```

- 棋盘原点 **(0,0)**，`BOARD_ROW0=0`、`BOARD_COL0=0`。
- 棋盘 15×15 格，每格 **2×2 tile**；总 30×30 tile，正好 480×480，上下拉满。
- 右侧 HUD：**列 30..39、行 0..29**（10×30 tile）。
- **去掉外框和 A-O / 1-15 坐标轴**：没有边距了，硬塞会挤掉棋盘。
  坐标信息保留在串口镜像里；如果一定要显示，放进右侧 HUD 的短行。

### 2.2 图块编号的硬约束

- `36..130` 是字库，`131..153` 是现有装饰，**绝对不要占**。
- 新棋盘象限图块允许用：**`154..255`（102 块）优先；不够再用 `0..35`（旧的 36 块棋盘区）**。
- **总数必须 ≤ 256**。做完在报告里给一张「图块编号 → 用途」表。

### 2.3 [!] 不要把 32×32 美术做成大 `.rodata` 表

当前 `tiles.h` 的 36 块棋盘图块 = **9,216 字节**，已经占在固件里。
如果新增 100 块象限图块 = **25.6KB**，RT-Thread 镜像（当前约 44KB）会直接涨到 70KB，
**装不进 64KB 区**（128KB 方案里 RT-Thread 拿的是 `0x10000~0x1FFFF`）。

**正确做法：在 `render_init()` 里运行时合成**（现在 23 个装饰图块就是这么做的，
见 `render.c` 的 `synth_*`）。这样：
- 新棋盘美术**不增加 `.rodata`**；
- 可以把旧的 36 块 `TILE_PATTERN` 表去掉，反而**省 9KB**；
- 唯一代价是 `render_init` 多跑几百微秒（上电一次，不影响帧率）。

> [!] render 线程栈只有 **4KB**。合成 32×32 时不要开 1KB 的栈缓冲区；
> 用 `static uint8_t` 工作区，或者按象限逐块合成（每次只算 16×16）。

## 3. 任务 ①：字距太大（P0，约 1 小时）

**根因**：现在是 **5×7 字模放大 2× = 10×14**，塞进 16×16 图块，横向空 6px。
把 5×7 横向拉 3 倍会让字又扁又胖，**不要这么做**。

**做法**：

1. 换 **8×8 字模**（7×8 有效 + 右侧 1px 间距，放大 2× = 16×16 正好填满）。
2. 字模来源二选一：
   - 导入公有领域 8×8 字库（如 `font8x8_basic`）；在 `gen_tiles.py` 里注明来源和 license；
   - 或自己重画 95 个 ASCII 字符（0x20~0x7E）。
3. 改 `gen_tiles.py` 的字模生成 → 重新生成 `font.h`（**不要手改 font.h**）。
4. `font.h` 的 `FONT_W` / `FONT_H` / `FONT_SCALE` 改为 `8 / 8 / 2`；
   `render_init()` 的放大代码是通用的，不用改逻辑，只确认偏移公式仍然居中。
5. `test_render.c` 里如果有按 5×7 算的字形断言，跟着改。

**验收**：HUD 一行 10 个字，字与字之间均匀、不粘、不扁；标题屏同样。

## 4. 任务 ②：棋盘拉满 + 右侧 HUD（P0，约 3 小时）

### 4.1 棋盘美术

- 每格画成 **32×32**，再切成 **4 个 16×16 象限**写显存。
- 建议尺寸（可按上板效果微调）：
  - 网格线宽 **4px**（当前 16×16 用 2px，按比例放大）；
  - 黑/白子半径 **12~13px**；
  - 光标半径 **14px**；
  - 星位点 **8×8**；
  - 最后一手标记：在右上象限画红色小三角/圆点，**运行时叠加**，不用单独存 18 块预合成图块。
- 9 种网格线形状 × 4 种状态（空/黑/白/光标）× 4 象限 = 原始 144 块。
  **必须去重**（很多象限是纯底色或同一条线），去重后写进允许的编号区（见 §2.2）。
- **不要再出现「一格一图块」的 16×16**：按 2×2 摆会变成四个小棋子，用户已经明确否掉。

### 4.2 渲染层改动

| 文件 | 改什么 |
|---|---|
| `render.h` | `BOARD_ROW0/BOARD_COL0` 改 0；新增「格 → 4 个 tile」的映射/接口；删除或停用 `render_board_frame`/`render_board_labels` |
| `render.c` | `render_tile_for()` 改为返回 4 个象限 tile（或新增 `render_cell_tiles()`）；`render_full()`/`render_cell()`/`render_move_cursor()` 每格写 **4 个 nametable 字节**（2 行 × 2 列） |
| `render.c` | `render_init()` 里增加 32×32 棋盘象限的运行时合成；`TILE_PATTERN` 表可去掉 |
| `main.c` | HUD 坐标全部改到右侧 10 列；菜单/标题屏字号与居中跟着 8×8 字库调 |
| `test_render.c` | 图块映射、星位、最后一手的断言按 2×2 更新 |

## 9. 最容易踩的坑

1. **不要把 5×7 横向拉宽** —— 又扁又胖，用户已经明确否掉。
2. **不要把 32×32 美术写进 `.rodata`** —— 会撑爆 RT-Thread 镜像；运行时合成。
3. **不要按 2×2 摆四个 16×16 格子** —— 会变成四个小棋子。
4. **不要占 `36..153`** —— 字库和现有装饰都在那里。
5. **不要忘了改 `render_full` 的写入** —— 一格现在是 4 个 nametable 字节，只改 `render_tile_for` 不够。
6. **不要用 libc / 浮点 / malloc** —— 固件是 freestanding；`render.c` 现有代码就是范例。
7. **不要追 `tb_gomoku` 的 FAIL** —— 已知仿真口径假象，板上全过。
8. **不要动 `rtl/`** —— CPU 线正在改 128KB，冲突了很难合。
