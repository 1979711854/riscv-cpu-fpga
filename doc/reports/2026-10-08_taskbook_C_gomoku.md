## 3. 任务 G1 · 人落子后立刻刷屏

### 现象与根因

AI 是**同步阻塞**跑的，`main.c:222` 的主循环：

```c
for (;;) {
    video_wait_vblank();          /* ① 等回扫 */
    input_poll(...);              /* ② 采样按键 */
    game_tick(&g_game, ...);      /* ③ AI 在这里阻塞 0.4~14.5 秒 —— 主循环停了 */
    draw_frame();                 /* ④ 刷屏 —— 只有 AI 跑完才会执行到 */
}
```

**所以你刚下的那颗子要等 AI 想完才一起出现。**

### 改法

在 `main.c` 里把"人走完"和"AI 走"拆开：**人落子 → 立刻 `draw_frame()` → 再跑 AI → 再 `draw_frame()`**。

**要点**：
- `game_tick()` 内部会同时处理人落子和 AI 应手，你需要判断这一拍**是谁走了**
- `g_game.ai_moves` 在 `game_tick` 前后会变（`main.c:266` 已经用了这个手法）—— 用它判断
- **不要改 `game_tick()` 的签名**，单测依赖它

**验收**：PC 端下完一颗子，**立刻**看到子落下（不用等 AI）。

## 4. 任务 G2 · AI 按层分批（**主要工作量**）

### 现象与根因

`ai.c:386` 的迭代加深：

```c
for (d = 2; d <= depth; d += 2) {     /* 2 -> 4 -> 6，逐轮做 */
    ... 完整搜一层 ...
}
```

**一轮搜完才进下一轮**，所以整个深度搜完之前主循环一次都回不来。

### 目标

**每次调用只加深一层，返回主循环刷屏后再继续。**

这样思考期间画面会跳 2~3 次，**而且 HUD 那行 `AI: NODES` 的数字在涨
—— 评委能看见 AI 在逐层加深搜索，演示效果反而更好。**

### 实现要点

**已有什么（别重复造）**：

```c
/* ai.c:80 */
#define AI_NODE_BUDGET  12000u

/* ai.c:285-290 已经有的中止机制 */
st->nodes++;
if (st->nodes > AI_NODE_BUDGET) { st->aborted = 1; return 0; }

/* ai.c:386 已经分层的循环 */
for (d = 2; d <= depth; d += 2) { ... }

/* ai.h:31-38 已经有统计结构 */
typedef struct {
    uint32_t nodes;
    uint32_t leaves;
    uint8_t  depth;
    uint8_t  aborted;
    int32_t  score;
} ai_stats_t;
```

**所以你要做的是「加一个可保存的搜索状态」**：

```c
typedef struct {
    gomoku_t     work;          /* 当前搜索棋盘（拷贝，不动调用方的）*/
    ai_move_tcand[AI_WIDTH];    /* 候选点 */
    int          cand_n;
    int          order[AI_WIDTH];
    int          next_d;        /* 下一个要搜的深度：2 / 4 / 6 —— 核心状态 */
    int          last_picked;   /* 上一轮完整搜完的最优着法索引 */
    int32_t      last_score;
    uint32_t     nodes_acc;     /* 累计节点数 */
    uint8_t      finished;      /* 1 = 已全部搜完 */
} ai_ctx_t;
```

然后：

```c
void ai_search_begin(ai_ctx_t *ctx, const gomoku_t *g, int level);
int  ai_search_step (ai_ctx_t *ctx, ai_ctx_t *out_move, uint32_t max_ms);  /* 0=还有下一层 */
```

**四条硬要求**：

1. **不要动递归结构本身**（`search()` / `do_move` / `ai_undo` 一行别改）
   —— 只在**外层迭代加深**那里切分。递归改迭代极易引入隐性 bug。

2. **每步之间要有时间上界**（建议 300ms），用 `hw_mtime()` 计时。
   **光按层切不够** —— HARD 的 6 层里最深那层可能自己就要 10 秒。

3. **打分只用「完整搜完」的轮次**。`ai.c:285` 的注释已经写明：
   > 中途退出的评分是**不可信**的（α-β 只保证完整搜完才有意义），
   > 所以调用方看到 `aborted` 必须丢弃本轮结果、用上一轮完整搜完的。

   **这个语义必须保持**，不能为了"每帧都有结果"而用半截评分。

4. **`ai_choose_move()` 必须保留**（270 项单测里有用），
   它可以内部用"循环调 `ai_search_step` 直到 `finished`"来实现。

**验收**：
- HARD 档思考期间画面**持续刷新**（不是静止）
- HUD 的 `AI: NODES` 在思考期间**数字在涨**
- 棋力**不得下降**：自对弈 20 局仍应 **14:5 胜 NORMAL**（或更好）
- `run_test.ps1` 仍 **270 项全过**

## 5. 关于"多线程"：不要上 RT-Thread

用户问过"G3 难度大吗？能体现 RT-Thread 吗？"

**RT-Thread 那条路被内存卡死了**：

```
gomoku 固件静态占用     22,507 字节
RT-Thread Nano 内核     ~15,000 字节
─────────────────────────────────
合计                    ~37,500 字节  >  32 KB 硬墙  ✗
```

**而且 RT-Thread 这个加分项已经单独拿到了**（2026-09-27 上板跑通，
banner + tick + ping/pong 双线程）。**不要为了它把五子棋塞进去。**

**G2 做出来的效果和"多线程"在演示上等价**：AI 思考期间画面持续刷新、
HUD 数字跳动。**单核 RTOS 的线程本质上也是时间片轮转**，
演示时评委无法分辨是"真线程"还是"协作式让步"。

## 6. 纪律与坑

### 6.1 必须跑的两条基线

```powershell
scripts\gomoku\run_test.ps1      # 270 项单测 + 交叉编译零警告
```

### 6.2 [!] `expectLines` 守卫会拦你，**那是守卫在工作**

固件大小变了就更新它（G2 会加状态结构，`mem.hex` 行数会变）。
**不要为了让脚本过而删守卫。**

### 6.3 [!] 中文 Windows 上的两个编码陷阱（都踩过）

1. `.ps1` **必须带 UTF-8 BOM**，否则 PowerShell 5.1 按 GBK 读，
   中文字面量会让引号配对失效，报"missing )"
2. 改 `.ps1` 后如果"改了但没生效"——
   用 Python 按字节读写（`core.v` / `build.ps1` 都栽过）

### 6.4 [!] 变短的字符串必须整行重写

串口/HUD 上"AI thinking (HARD 6-ply)..."变短时，
**必须用空格补齐或整行重写**，否则残留旧字符。

### 6.5 任何一次综合都会覆盖 `generate_bitstream\cpu_top_board.sbit`

所有位流文件名和字节数**完全一样**（9,188,552）。
归档名必须带配置：`_dual_` / `_single_`。
