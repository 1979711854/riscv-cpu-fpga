## 2. 【已完成】根因修复 + 三处**口径更正**（都是这轮踩实的）

### 2.1 `wb_rdata_snap` 一行修复（`rtl/core/core.v`）
停顿沿写成 `ex_mem_ld_fast ? ld_early_data : mem_rdata` —— 用 **EX/MEM 级**（下一条指令）
的信号去选 **MEM/WB 级**（本条指令）的数据。I-Cache 缺失冻结时把下一条 load 的值写回 ⇒ 跑飞。
**修法：停顿那支只能取 `mem_rdata`**。触发需要**四个条件同时成立**：
`EARLY_LD=1` + `ICACHE_EN=1`（提供大量停顿）+ `DCACHE_EN=1` + 普通 load 在 WB 且快通路 load 在 EX/MEM。
见 `2026-10-12_icache_wb_snap_fix.md`。

### 2.2 [重点] 口径更正 1：**I+D 的周期代价是 +0.95%，不是文档旧写的 +9.8%**

| 口径 | 拍/迭代 |
|---|---|
| 无 Cache（`EARLY_LD=1`）| 241,633 |
| **I+D 全开（`EARLY_LD=1`）** | **243,933（板上）/ 244,034（仿真）** ⇒ **+0.95%** |
| I+D 全开（**`EARLY_LD=0`**）| 265,408 ← **文档旧值，作废** |

⇒ **"I-Cache 缺失每迭代 +22,000 拍"的结论作废**。I-Cache 缺失虽有 **2,455 次/迭代**，
但冻结的拍几乎**全藏在原有的气泡里**（访存/分支停顿）。
**直接后果：v7 §8 里"压 I-Cache 缺失通路 ≈ +6%"这条不再值钱**（上限只剩 ~0.9%）。

### 2.3 口径更正 2：`DESIGN_REV` 漏递增已补
根因修复那次提交**忘了**约定 42（改 RTL 必须递增 `DESIGN_REV`），导致修好的位流与失败的
`fa957dbd` 串口首行**一模一样（`0x20261015`）**。已补到 **`0x2026_1016`** 并重出位流 ⇒
板上一眼区分。

### 2.4 口径更正 3：**跨仓库比 `.sbit` md5 无意义**
同一设计在两个仓库副本综合，**网表逐字节相同、时序逐位相同**，但 `.sbit` md5 不同
—— 因为**文件里内嵌了工程路径**。**同仓库内** md5 才是稳定标识。

## 5. 各任务细节

### A.【P0】把 I+D 的主频拿回来 —— **现在唯一值钱的 Cache 方向**
**为什么**：I+D 的 −10.9% 里 **−10.0% 是主频**，周期只 −0.95%。
**关键路径**（v7 已定位）：`D-Cache 数据阵列 → 前递/分支/重定向 → fetch_addr → I-Cache tag 比较 → 命中`（15~17 级、Route 占 63%）。
**已排除**：压逻辑没用（是布局拥塞）；容量已 4 KB/侧；`create_region` 在 TCL 里不可用。
**两条没试过的路**：
1. **PCE 图形界面做区域约束**，把两个 Cache 拉到核附近（手册 `doc/Physical_Constraint_Editor_User_Guide.pdf`，**没试过**）；
2. 把 **I-Cache 的 tag 比较移出取指关键链**（结构可行，但会改变"指令流取自 Cache"的语义，**答辩会被追问**）。
**验收判据**：I+D 在 **85 MHz** 下 CPU 域 setup ≥ 0、失败端点 0，且板上 `Total ticks ≈ 4116 × 241,633`
（注：I+D 的实际拍数是 **243,933**，ITER 要按它重算：`85,005,100 × 11.7 ÷ 243,933 ≈ 4,077`）。

### B.【P0】应用场景（第 4 权重，**当前完全空白**）

旧任务书 §1.2 的"32 KB 约束"已勘误，见 `doc/reports/2026-10-12_gomoku_erratum_and_task.md`。

## 6. 纪律（交接必看，都是踩过的）

1. **改 RTL 后 `DESIGN_REV` 必须加一**（`rtl/core/csr_file.v`，现在 `0x2026_1016`）——
   它证明的是 **RTL 版本**，**证明不了 parameter 开关**，两件事都要看。
2. **"带开关"的位流必须验网表**：
   ```bash
   grep -aic dcache pds/RV32I_1/place_route/seed_*/cpu_top_board_pnr.netlist   # 必须 > 0
   grep -aic icache pds/RV32I_1/place_route/seed_*/cpu_top_board_pnr.netlist   # I+D 版也必须 > 0
   ```
   并核对 slack 与该配置的已知值（Cache 关 **+0.045** / 只 D **+0.151** / I+D@85 **−1.143** / I+D@76.5 **+0.589**）。
3. **同一个 PDS 工程目录不能并发综合**；**要并行就并到不同仓库副本**（本轮就是这么跑的 85 + 76.5）。
4. **综合前 `git status`**；**每次上板前重跑 `sync_firmware.ps1`**（`mem.hex` 过期时 PDS **零报错**）。
5. **改频率必须同步 3 组东西**：`pll.idf` 的 `STATIC_RATIO0` + `ip_generate.exe -i pll.idf`（**不是**改
   `CLKOUT0_REQ_FREQ`）→ `cpu_top_board.v` 的 `UART_DIV`（f/115200）→ `core_portme.c` 的
   `EE_TICKS_PER_SEC` → 重算 `ITER`。**做完必须全部还原**（不还原的话跑分位流的时钟就变了）。
6. **`.sbit` 不入库**（9 MB/个，只入库索引）⇒ **队友必须自己综合**（§7 有步骤）。
7. **烧录三步走全**：`Scan Device → Assign New Configuration File → Program`；烧完**先对 md5**
   （`generate_bitstream\cpu_top_board.sbit` 这个名字看不出哪一版）。
