> [!] 另外记一条口径关系（这次才量出来）：
> **`Total LUTs` = `LUTs as logic` + `LUTs as dram`**，其中 dram 数 = LUT-RAM 原语数

| 依据 | 512 深仍覆盖 CoreMark 报告（约 440 字节）；`busy` 在 `cpu_top` 里未接（`.busy ()`），缩深度只影响连续大段 printf 的阻塞时长 |
| 实测 | 7,740 → **7,658**（logic −18 / RAM −64）；WNS **+0.304 → +0.460**、Fmax **79.2959**、totalEP 21,135 → 20,559 |
| 功能 | region cycles 217,088 **逐位不变**、四 CRC 不变、riscv-tests 49/1/0、own_tests 8/0 |
| 结论 | 零风险、**顺手把指标②抬了 0.97 MHz**。若只看②，L1 单独是最好的版本（见 §5 取舍） |

### 3.2 L2 · BTB 256 → 32 项（并入 `e7c35a2`）

| 项 | 内容 |
|---|---|
| 改动 | `core.v`：`btb_tag/btb_target [0:255]→[0:31]`、`btb_valid [255:0]→[31:0]`、`btb_idx_p/w` 取 `PC[6:2]`、复位 `32'd0` |
| tag 策略 | **保持 24 位（PC[31:8]）**，即索引只看 `PC[6:2]`、**`PC[7]` 不参与匹配** ⇒ 相差 128 B 的两个 jalr 共用条目（别名） |
| 为什么安全 | 目标猜错由 EX 级 `ex_target_wrong`（`id_ex_pred_taken && (rs1_val&~1) != id_ex_pred_target`）冲刷纠正 —— 只掉命中率，**不可能静默错值** |
| 实测 | 7,658 → **7,092**（logic −374 / RAM −192）、FF 3,466（−224 = `btb_valid` 256→32） |
| 拍数 | **217,088 逐位不变**（`btb pred 44` 不变）⇒ CoreMark 里间接跳转极少，32 项完全够 |
| ⚠ 时序 | **−0.099 ns / 11 个失败端点**（Fmax 75.93）⇒ 单独**不可交付** |

> [!] **为什么减了 566 却只掉 192 个 RAM 单元**：256 深的 LUT-RAM 阵列要"4 个 RAM64X1 + 16:1 输出 mux + 地址译码"
> 才凑出 1 位，mux/译码被综合成**逻辑 LUT**；降到 32 深后每位只要 1 个 RAM64X1、无外圈逻辑。
> 所以深表的真实成本 ≈ RAM 单元 × 2。**这条是后续所有"缩深度"候选的定价依据。**

### 3.3 L3 · BHT tag 24 → 8 位（深度仍 256，并入 `e7c35a2`）

| 项 | 内容 |
|---|---|
| 改动 | `core.v`：`bht_tag [23:0]→[7:0]`，比较/写入改 `PC[17:10]`；索引仍 `PC[9:2]`、深度仍 256、`bht_ctr`/`bht_valid` 不变 |
| 为什么零风险 | 索引 + tag 覆盖 `PC[17:2]` = 256 KB，而两份镜像都在 `0x0~0x1FFFF`（128 KB）内 ⇒ **零别名、预测率逐位不变** |
| 实测 | 7,092 → **6,932**（RAM 316→188）；WNS **−0.099 → +0.311**、Fmax **78.3699**、0 失败端点、totalEP 16,670 |
| 拍数 | **217,088 逐位不变**、`mispredict` 仍 1,543 |

**被否的第一次尝试（128 项版）**：

| 项 | 128 项版（深度减半） | 256 项 + 8 位 tag（采纳） |
|---|---|---|
| region cycles | **217,892（+804 拍 / +0.37%）** | 217,088（0） |
| mispredict | 1,548（+5） | 1,543（0） |
| 判定 | ❌ 超门槛（上限 +651 拍 = +0.3%） | ✅ |

> 128 项版**只跑到仿真就被否**（没过拍数门槛，没有为它出流），
> 所以"深层阵列外圈 mux 会更亏"是**从 L2 数据推断**的，不是对该版本的直接测量 —— 如实记录。
> 结论：**缩 tag 宽度白拿、缩表深度要付命中率**。

## 6. 这次学到的反例（比成功更重要）

1. **减 LUT 与时序非单调**：L2 减了 566 个 LUT，WNS 反而掉 0.56 ns（11 个失败端点）；再叠一个更小的 L3（−160），又回到 +0.311。失败路径仍是 `DRAM 读 → load 解包 → 分支比较 → if_addr_d`，**与被改的预测器无关** ⇒ 主导因素是布局扰动，不是逻辑深度。**任何一轮都必须实测，不能靠"少点逻辑总归好"推**。
2. **L2 与 L3 必须一起交付**：只回退 L3（回到 L2 单独）会得到一个不收敛的版本；只回退 L2 保留 L3 也需要重新出流验证。
3. **`pds/` 目录里的旧产物会骗人**：主干工作树里的 8,133 / 8,762 就是这么来的。**任何"资源/时序"结论，都必须先确认这份 `run.log` / `.rtr` 是哪一次、哪份 RTL 跑出来的。**
4. **开工前先建干净基线**：本次在 `D:\_lut_base`（`deliver-b45941d6`，未改 RTL）跑一遍完整流程，才拿到可信的 7,740 / +0.304，也才有后面所有的 Δ。**这 10 分钟不能省。**
5. **改 LUT-RAM 深度必须同时改两侧**（`bht_hit_p` 与 `bht_hit_w`、`btb_idx_p` 与 `btb_idx_w`），只改一侧 = 静默错预测（拍数暴涨但 CRC 仍对）。

| seed | WNS | Fmax | failEP | totalEP | 判定 |
|---|---|---|---|---|---|
| 8 | +0.147 | 77.3754 | 0 | 16,681 | 不如 10 |
| **10** | **+0.311** | **78.3699** | 0 | 16,670 | ✅ **仍最优，保持** |
| 16 | +0.069 | 76.9112 | 0 | 16,718 | 不如 10 |

结论：三个采样点极差 0.242 ns，**seed 10 在两个不同网表上都赢** ⇒ **不换 seed**，
