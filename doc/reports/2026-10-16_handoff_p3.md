## 2. 根因（已定位到门级路径，不用重查）

`pds/RV32I_1/report_timing/cpu_top_board.rtr`（seed 6）里 CPU 域最差路径：

```
u_video/u_core/u_pal DRAM 读出 → vid_rdata
  → load_half_b[7] → load_data_b_4[16] → wb_data_b[27]      ← lane B load 解包
  → b_alu_a[27] → u_alu_b/result_207[0] → alu_result_b[0]   ← lane B ALU 加法器
  → N616_5 → if_addr_d[5] → imem_addr[3] → imem_addr2[12]   ← 取指地址 mux
16 级逻辑；Logic 36.5% / Route 63.5%
```

**这就是 P2 任务书 `2026-10-16_laneb_timing_fix_taskbook.md` §3 预警的
"`load_misaligned_b` 背后的 `alu_result_b` 加法器锥被并进 `fetch_addr`"。**
0 档能用 7 处 `LANEB_MEM` 常量折叠把整条删掉（+0.004 ns）；**1 档它是活逻辑，折叠不掉。**

## 3. 下一会话第一件事：P3.5 —— 砍关键路径（**按(A)→(B)→(C)→(保底) 顺序做**）

**目标判据**：1 档仍需 `CoreMark = 217,088` + 四 CRC 逐位一致（证明只动时序、不动语义），
且 PDS CPU 域 **WNS ≥ 0 @85.0051 MHz**；余量最好回到 rev1023 的 **+0.330 ns** 量级。

**缺多少**：可达 12.465 ns vs 需求 11.764 ns ⇒ **缺 0.701 ns**；要到 rev1023 的 87.46 MHz 需砍 1.03 ns。
路径三段串联（`.rtr` 1360–1394 行）：

| 段 | 内容 | 修法 |
|---|---|---|
| 前 | palette DRAM → `vid_rdata` → lane B 解包 → `wb_data_b` → `b_alu_a` → **`u_alu_b` 32 位加法器** → `alu_result_b` | **(A)** 未对齐判定改 2 位窄逻辑 |
| 后 | `load_misaligned_b` → `if_addr_d` → `imem_addr` → **`+14'd1` 进位链 → `imem_addr2`** → BRAM | **(B)** 第二取指地址并行化 |
| 兜 | 整条链过长 | **(C)** lane B trap 改寄存器输出（仅异常路径 +1 气泡） |

### (A) 首选：`b_addr_low` 用 2 位加法（1 级 LUT、无进位链、等价可证）

`core.v:1394` 现状：`wire [1:0] b_addr_low = alu_result_b[1:0];`
改成：`wire [1:0] b_addr_low = rs1_val_b[1:0] + id_ex_b_imm[1:0];`

* **等价性**：`control.v:101-106` 的 OP_LOAD ⇒ `alu_a_sel=0 / alu_b_sel=1 / alu_op=0(ADD)`
  ⇒ `alu_result_b[1:0] ≡ rs1_val_b[1:0] + imm_b[1:0]`；且 `b_mem_unaligned` 只经
  `load_misaligned_b`（已 AND `id_ex_b_mem_read`）使用 ⇒ **只在 load 时有意义，替换严格等价**。
* **别一起改 `exc_tval`**（`core.v:1450`）：它用全 32 位地址进 CSR 寄存器，不在取指路径上。
* **判据**：`tb_laneb_ld` 用例 8（mcause=4 / mtval=出错地址 / mepc=肇事 PC 三条全过）
  **且 CoreMark 必须仍是 217,088**。

### (B) 若 (A) 不够：`core.v:839` 的 `imem_addr2 = imem_addr + 14'd1` 解耦

它是串在 `imem_addr` 之后的**第二级加法**（还有 14 位进位链 + 1.295 ns 长线进 BRAM）。
从 `fetch_addr[15:2]` 各自并行算，或把 `+1` 并进取指地址 mux 的同一级。
⚠️ `imem_addr2` 的宽度/对齐纪律见 `core.v:834-838` 与 `addr_map.vh` 头部清单。

### (C) 兜底 RTL 方案：lane B 的 trap/flush 变寄存器输出

允许"lane B 的异常下一拍才冲刷取指"（只在异常路径上多 1 拍气泡），fetch 路径自然断开。
* 风险：`trap_pc`/`mepc` 语义要重证（约定 56/57 的冻结拍纪律同样适用）。

### (保底) 不想动 RTL 时：PLL 换 `RATIO0=14.0` → 81.97 MHz

* VCO = 85.0051 × 13.5 = 1147.57 MHz ⇒ ÷14.0 = **81.97 MHz**（周期 12.1997 ns）
* 1 档可达 12.465 ns ⇒ 该频率下**预计 slack ≈ +0.27 ns**（必须实测坐实）
* 物理分 = 81.97e6 ÷ 217,088 = **377.6 分**（比交付 370.31 **+2.0%**）
* 代价：技能 §5 的"改频三处联动 + 事后还原"（`pll.idf` STATIC_RATIO0 → `ip_generate.exe`
  → `UART_DIV` → `core_portme.c` 的 `EE_TICKS_PER_SEC`）+ **必须重算 ITER**。
  现成的 76.5052 MHz 档反而更差（352.4 分），别用。
* **完全放弃的选项**：维持 `LANEB_MEM=0`（把 +5.76% 效率储备搁置）。

> **口径提醒**：赛题主公式 `Score = Iterations/(Time×Freq)` = CoreMark/MHz **与主频无关** ——
> 1 档在效率上已经赢 5.76%（4.6064 vs 4.3555）；**391.6 分只是"85 MHz 且时序过"的物理读数**，
> 掉的是指标(2) Fmax，不是主分。所以 P3.5 是"把 Fmax 拿回来"，不是"补主分"。


> [!] **别动 `pair_now` / 别给 `fetch_addr` 新增 mux 腿**（任务书 §8.6 明令）。
> [!] 若改了 RTL，**递增 `DESIGN_REV`**（`csr_file.v`）并同步 `doc/paper/论文框架_v1_20261012.md` §0 口径。

## 6. 本会话踩过的坑（勿重蹈）

* **`run_own_tests.ps1` 默认删 `sim/tests/build/`**（`-KeepHex` 才留）⇒ 想手工
  `vvp +PAIRTRACE` 要么加 `-KeepHex`，要么手工 `riscv-none-elf-gcc` 编到 `sim/programs/`。
* **`run_coremark.ps1 -SkipBuild` 用的是 `sim/programs/coremark.elf` 的既有 ITER**：
  跑过 `build_bitstream.ps1` 之后它是 **ITER=4332**（ticks 会变成 ~9.9 亿），
  要么去掉 `-SkipBuild` 重建 ITER=1，要么把 ticks 除以 4332 再比。
* **PDS 不因为时序不过而失败**：`6a040f79` 照样 8.76 MB 正常生成 ⇒ "构建成功" ≠ "能上板"。
* 各 seed 的 `place_route/seed_*/` 只保留被选中的那个（本次只有 `seed_6/`）。
* `ps1` 编辑后**必须确认 UTF-8 BOM 还在**（`EF BB BF`），否则 PS 5.1 按 GBK 读、中文注释吃掉引号配对。
