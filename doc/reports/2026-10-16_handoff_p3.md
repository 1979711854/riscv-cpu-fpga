## 2. 根因（已定位到门级路径，不用重查）

`pds/RV32I_1/report_timing/cpu_top_board.rtr`（seed 6）里 CPU 域最差路径：

```
u_video/u_core/u_pal DRAM 读出 → vid_rdata
  → load_half_b[7] → load_data_b_4[16] → wb_data_b[27]      ← lane B load 解包
  → b_alu_a[27] → u_alu_b/result_207[0] → alu_result_b[0]   ← lane B ALU 加法器
  → N616_5 → if_addr_d[5] → imem_addr[3] → imem_addr2[12]   ← 取指地址 mux
16 级逻辑；Logic 36.5% / Route 63.5%
```

**这就是 P2 任务书 `2026-10-16_laneb_timing_fix_taskbook.md` §3 预警的
"`load_misaligned_b` 背后的 `alu_result_b` 加法器锥被并进 `fetch_addr`"。**
0 档能用 7 处 `LANEB_MEM` 常量折叠把整条删掉（+0.004 ns）；**1 档它是活逻辑，折叠不掉。**

## 3. 下一会话第一件事：P3.5（按代价排序的候选修法）

**目标判据**：1 档仍需 `CoreMark = 217,088` + 四 CRC 逐位一致（证明只动时序、不动语义），
且 PDS CPU 域 **WNS ≥ 0 @85.0051 MHz**、余量回到 rev1023 的 **+0.330 ns** 量级。

1. **给 lane B 的未对齐判定换窄逻辑**（首选，纯组合改写、不动流水线）
   `load_misaligned_b` 实际只需要"地址低 2 位 + funct3 的宽度"：
   `lh` 越界 ⇔ `(addr[0])`（且 `offset[1]==0` 时还要看 `addr[1]`）、`lw` 越界 ⇔ `addr[1:0] != 0`。
   即用 `id_ex_b_rdata1[1:0]`/`imm_b[1:0]` 的 **2 位加法**替代 32 位 `alu_result_b`。
   * 风险：跨字边界要写全（`lh` 在 `offset=3` 时也越界）；**判据 = `tb_laneb_ld` 用例 8**
     （mcause=4 / mtval=出错地址 / mepc=肇事 PC 三条都要过）。
2. **把 lane B 的 trap/flush 变成寄存器输出**（多 1 拍气泡，只在异常路径上）
   若允许"lane B 的异常下一拍才冲刷取指"，长链自然从 fetch 路径断开。
   * 风险：`trap_pc`/`mepc` 语义要重证（约定 56/57 的冻结拍纪律同样适用）。
3. **兜底**：维持 0 档交付（`parameter LANEB_MEM = 0`），把 1 档当效率储备。

> [!] **别动 `pair_now` / 别给 `fetch_addr` 新增 mux 腿**（任务书 §8.6 明令）。
> [!] 若改了 RTL，**递增 `DESIGN_REV`**（`csr_file.v`）并同步 `doc/paper/论文框架_v1_20261012.md` §0 口径。

## 6. 本会话踩过的坑（勿重蹈）

* **`run_own_tests.ps1` 默认删 `sim/tests/build/`**（`-KeepHex` 才留）⇒ 想手工
  `vvp +PAIRTRACE` 要么加 `-KeepHex`，要么手工 `riscv-none-elf-gcc` 编到 `sim/programs/`。
* **`run_coremark.ps1 -SkipBuild` 用的是 `sim/programs/coremark.elf` 的既有 ITER**：
  跑过 `build_bitstream.ps1` 之后它是 **ITER=4332**（ticks 会变成 ~9.9 亿），

* 各 seed 的 `place_route/seed_*/` 只保留被选中的那个（本次只有 `seed_6/`）。
